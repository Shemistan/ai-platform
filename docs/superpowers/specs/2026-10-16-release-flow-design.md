# Выпуски: от «собрано» до «опубликовано и посмотрено»

## Зачем

Реальные данные платформы (`data/`, 15–16.10.2026): 12 выпусков, до канала
ботом дошёл один. Пять стоят на «⏸ нажми Опубликовать», один упал на
публикации из-за канала 9:16 без шортса, четыре брошены на картинках.
Статью про Discord создавали 4 раза, дайджест за 15.10 — 4 раза: каждый раз
картинки и озвучка генерировались заново. Статьи на 17 и 38 минут озвучки
собирались ночь (21:38 → 04:25). Дайджест каждое утро запускается руками.
Что было после публикации, платформа не знает.

**Что сказал человек.** «Реализуй все пункты» — восемь улучшений из разбора
платформы: доска выпусков, продолжение вместо пересоздания и кэш, проверка
до запуска, черновик и длинные статьи, дайджест по расписанию, отклик
каналов, уборка данных, README и smoke-прогон.

## Критерии успеха

1. Страница «Выпуски» показывает все выпуски всех сценариев в группах
   «ждёт тебя / идёт / готово / черновики»; у ждущего — какой шаг, что
   нужно и кнопка действия; публикация ждущего выпуска — в один клик.
2. Повторное создание выпуска по тому же дню или тому же тексту предлагает
   открыть существующий; «Копия выпуска» переносит готовые результаты.
   Картинка, ролик или озвучка с теми же входами второй раз не генерируются
   — берутся из кэша, в журнале «из кэша».
3. У выпуска видны оценка времени (картинки, ролики, озвучка, сборка — по
   истории задач этой машины) и предупреждения до запуска; несовместимость
   каналов и настроек видна сразу, публикация проверяет все каналы до
   первой отправки.
4. Настройка «Черновик» собирает видео без картинок и роликов в половинном
   кадре; «Сделать чистовик» — одна кнопка. Для статьи длиннее ~12 минут
   озвучки — «Разбить на серию» (по главам/абзацам, без LLM) и «Сделать
   выжимку» (LLM, 5–8 минут).
5. Расписание дайджеста в «Настройках»: время и день (вчера/сегодня);
   выпуск создаётся и запускается сам, уведомление macOS (или своя команда)
   — когда выпуск ждёт человека или упал.
6. Отклик: при публикации в Telegram запоминается id сообщения и число
   подписчиков; «Обновить отклик» (и раз в сутки сам) подтягивает
   подписчиков и, у публичных каналов, просмотры; у пакетов ручной загрузки
   просмотры вводятся руками. На «Выпусках» — сводка «что работает»: средние
   просмотры по сценарию, длине и шортсу.
7. Выпуск можно убрать в архив (с доски и из списков). «Уборка» в
   «Настройках»: сколько места занимает каждая область и удаление старше N
   дней — завершённых задач вкладок, записей кэша и архивных выпуска;
   неархивные выпуски не удаляются никогда. Можно включить ежедневно.
8. README отражает новое и то, что проверено на настоящих моделях; `make
   smoke` — короткий прогон на настоящих моделях с замером времени.
9. `./check` зелёный: всё новое покрыто тестами на фейках.

## Решения

- **Доска — модуль studio, не новый сервис.** `GET /api/studio/board`
  отдаёт выпуски с «вниманием» (шаг, статус, заметка), опубликованностью и
  откликом; страница `static/board/`, первая в группе сценариев шапки, со
  счётчиком «ждёт тебя».
- **Дубликат — по источнику.** У дайджеста — день, у статьи и поста — sha256
  текста (`source` в project.json). Создание с тем же источником → 409 с
  `existing`; `force_new: true` создаёт новый. Архивные не считаются.
- **Кэш — по входам генерации.** `data/studio/cache/<sha>.<ext>`, ключ —
  JSON входов: картинка (промпт, модель, размер, увеличение), ролик (промпт,
  модель, пресет, длительность), озвучка (текст, движок, голос, скорость).
  Записи — жёсткие ссылки (копия, если нельзя), mtime обновляется при
  попадании: уборка удаляет давно не нужные.
- **Оценка — по истории.** Средние по завершённым задачам вкладок:
  секунды на картинку по модели (и на увеличение), на ролик по модели,
  секунды озвучки на символ по движку; сборка — доля от длины озвучки по
  прошлым сборкам (шаги теперь пишут `started_at`/`finished_at`). Нет
  истории — консервативные значения по умолчанию. Это ориентир, не обещание.
- **Предупреждения — отдельно от ошибок.** `preflight(project)` не мешает
  запуску, а показывает: каналы 9:16 без шортса, каналы с проблемой токена,
  неустановленные модели, постер/картинки «загружу сам», длинный текст.
  Публикация сначала проверяет все выбранные каналы и только потом шлёт.
- **Черновик — настройка `draft`.** Шаги картинок и роликов пропускаются,
  сборка — с масштабом 0,5 (поверх `AIP_RENDER_SCALE`). Смена `draft`
  сбрасывает картинки, ролики, сборку и шортс.
- **Серия — без LLM.** Главы — строки-заголовки (`#`, `##`) или, без них,
  группы абзацев до ~1000 слов; каждая часть — новый выпуск «Видео по
  статье» с теми же настройками и названием «… — часть N из M». Выжимка —
  LLM по промпту `prompts.summary`, новый выпуск.
- **Расписание и уведомления — в процессе платформы.** Поток studio раз в
  минуту: наступило время и выпуска за этот день нет → создать и запустить.
  Пропущенное (платформа была выключена) догоняется в тот же день, не
  позже. Уведомление — при переходе выпуска в «ждёт» или «ошибка»:
  `AIP_NOTIFY_CMD` (текст на stdin; по умолчанию `osascript` на macOS), в
  демо — запись в `data/notifications.log`.
- **Отклик — Bot API и публичная страница.** Bot API не отдаёт просмотры
  сообщений, поэтому: подписчики — `getChatMemberCount`, username канала —
  `getChat`; просмотры — со страницы `https://t.me/<username>/<id>?embed=1`
  (только у публичных каналов). Снимки — в `published.json` у записи канала:
  `members_at_publish`, `stats: [{at, views, members}]`. Ручные просмотры —
  `POST …/stats` с `{channel, views}`.
- **Уборка удаляет только восстановимое.** Задачи вкладок (их файлы
  выпуски уже скопировали к себе), кэш, архивные выпуски старше N дней.
  Идущие задачи и неархивные выпуски не трогаются.
- **smoke — тот же сервер в процессе.** `python -m aiplatform.smoke` поднимает
  платформу на временных данных и настоящих моделях, делает одну картинку,
  одну фразу озвучки и черновик статьи до видео, печатает время шагов. С
  `--fake` гоняется в тестах.

## Что не входит

- Публикация в YouTube/TikTok по API (нужен OAuth — как и раньше, пакеты).
- Просмотры приватных каналов Telegram: без MTProto их не получить.
- Перенос старых выпусков в кэш: кэш наполняется с новых генераций.
