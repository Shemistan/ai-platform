# Перенос narrator в платформу: движок и все его функции в UI

## Зачем

Старый сервис `~/my_track/07_offline_text-to-word` (narrator) хотят удалить, а
платформа без него не работает: «Аудио», сбор дайджеста и публикация в
Telegram вызывают его CLI и читают его файлы. Кроме того, у narrator есть
функции, которых в платформе нет вовсе: библиотека статей, бот с
подписчиками, обзоры недели и месяца, здоровье источников, проверка озвучки
распознаванием, образцы голосов, вкладка «Пост».

Цель: после переноса старый каталог можно удалить, а всё, что он умел,
делается из платформы, причём каждая функция живёт там, где её ищут.

## Решение 1. Движок — `app/narrator/` в этом репозитории

Код narrator (Python с тяжёлыми зависимостями: torch, f5-tts, mlx-audio,
faster-whisper) переезжает в монорепозиторий как отдельный сервис
`app/narrator/` со своим `pyproject.toml`, `uv`-окружением, тестами и
`make check`. Платформа остаётся без Python-зависимостей и зовёт движок как
CLI — как и сейчас, только путь по умолчанию теперь свой:
`AIP_NARRATOR_DIR` = `app/narrator` рядом с `app/platform`.

Почему не вшить в `aiplatform`: платформа принципиально stdlib-only и
запускается `python3 -m`, а движку нужны модели и сотни мегабайт пакетов.
Отдельный процесс на задачу заодно освобождает память GPU между задачами.

Что переезжает: `src/narrator` (кроме старого веб-UI), `config/`, `assets/`,
`tools/fetch-models.sh`, `tools/move-models.sh`, тесты, `docs/skills/`
(skill `youtube-news` для обзоров), регламент агентов из `CLAUDE.md`
(разделы «Озвучка статьи», «Телеграм-каналы», «Дайджест новостей», «Судья
дайджеста», «YouTube: обзор недели и месяца») — в `app/narrator/CLAUDE.md`.

Что не переезжает — заменено платформой:
- старый веб-UI `narrate ui` (`src/narrator/ui/`) — его вкладки теперь в
  платформе;
- ролик статьи на Remotion (`film.py`, `tools/film/`) — его делает сценарий
  «Видео по статье»;
- видео-версия дайджеста на Slidev (`news/slides.py`, `tools/slides/`) — её
  делает сценарий «Дайджест новостей».

Данные остаются личными и в git не идут: `app/narrator/library/` (статьи,
база новостей, `telegram.json`), `app/narrator/telegram_tems.md`,
`app/narrator/bot_token.md`. Перенос — один раз скриптом
`app/narrator/tools/import-old.sh <старый каталог>` (копирует библиотеку,
каналы и токен, ничего не удаляет). `library_root()` по умолчанию —
`app/narrator/library` основного checkout (из worktree — тоже он: библиотека
одна на машину).

### Мост для страниц: `narrate bridge …`

Страницам нужны данные, а CLI печатает текст для человека. Новый модуль
`narrator/bridge.py` — подкоманды, которые печатают JSON и ничего не
спрашивают:

| Команда | Что отдаёт |
|---|---|
| `engines` | движки: голоса с записанными образцами, шаги и скорость по умолчанию, почему не запустится; есть ли модель проверки |
| `preview` (текст на stdin) | как прочитает модель: текст, число изменённых строк, замечания |
| `split` (текст на stdin) | статьи markdown-файла: заголовок и число слов |
| `library` / `article <id>` | статьи библиотеки со статусами / карточка, текст и отчёт проверки |
| `sources` / `failed` / `top --date` | источники с журналом сбора и пользой / упавшие / события дня |
| `issue --date` | выпуск дня: вердикт судьи и `review.md` |
| `reviews` / `review <id>` | обзоры недели и месяца / файлы одного обзора |
| `subscribers [--sync]` / `unsent` / `bot` | подписчики / неотправленные озвучки / токен и имя бота |
| `voices` | образцы голосов-клонов: какие записаны, длительность, текст |
| `models` | модели озвучки на диске |

`narrate say` получает `--check-json <файл>`: структурный отчёт проверки
(общий процент, абзацы ниже порога, неуслышанные слова), как было в старом
UI.

## Решение 2. Где что в интерфейсе

Шапка группами — сначала инструменты, затем сценарии выпуска, материалы и
обслуживание:

```
Фото · Видео · Аудио | Дайджест новостей · Видео по статье · Пост в канал | Статьи · Новости | Каналы · Обновления
```

Принцип: функция живёт там, где о ней думают. Озвучка текста — в «Аудио»;
всё про статьи библиотеки — в «Статьях»; про источники и обзоры — в
«Новостях»; куда уходит контент и кто подписан — в «Каналах»; модели — в
«Обновлениях».

### «Аудио» — дополняется

- Над полем текста: «Взять текст…» (статья или дайджест из библиотеки) и
  «Из файлов…» (md можно и перетащить в поле). Файл с двумя и больше
  статьями (`# Заголовок` или `---`) показывает список «Найдено N статей» и
  кнопку «Все в очередь» — каждая отдельной задачей, до 100.
- Под полем: строка «Произношение: 4 строки переведены · 2 замечания» и
  раскрывающийся блок «Как прочитает модель» — нормализованный текст и
  замечания с номерами строк. Считается на лету, с задержкой после ввода.
- Настройки: недоступный движок виден, но выключен, с причиной; «Шаги» у
  ESpeech и Supertonic; галочка «Проверить распознаванием» (если модель
  проверки есть).
- Результат: «Проверка» — общий процент и абзацы ниже порога, неуслышанные
  слова подсвечены; кнопка «Текст в редактор».
- Ссылка «Образцы голосов…» рядом с голосом — диалог: голоса-клоны со
  статусом, прослушать образец, перезаписать (Charon — из Gemini TTS по
  ключу, Shem и Shem-v2 — своя запись и её текст).

### «Статьи» — новая вкладка `/library/`

- «Добавить статью»: ссылка → «Скачать» (`fetch`) или «Вставить текст»
  (название, текст). Текст для озвучки — как есть или «Подготовить агентом»
  по регламенту «Озвучка статьи» (`claude -p`).
- Список статей по дням: название, длительность, движки, проверка в %,
  отправлено в канал. Фильтр: все, не озвучены, не отправлены.
- Карточка: текст для озвучки (правится), описание для реестра, плеер,
  отчёт проверки; «Озвучить», «Проверить», «Отправить в канал…», «Сделать
  видео» (новый выпуск «Видео по статье» с этим текстом).
- Сверху над списком: «Озвучить новые», «Переозвучить все», «Отправить
  неотправленные (N)», «Считать отправленными».
- Долгие операции — задачи с прогрессом и логом в общей очереди GPU.

### «Новости» — новая вкладка `/news/`

- «Источники»: вид, вес, последний сбор (ок или сбой, когда, сколько
  нового), польза (важных из разобранных), пометка «мало пользы»; кнопка
  «Собрать» у строки и «Собрать все»; фильтр «только со сбоем».
- «Главное за день»: день и события по важности с источниками.
- «Добор упавших»: источники со сбоем и ошибкой, «Добрать агентом».
- «Обзоры для YouTube»: «Обзор недели», «Обзор месяца»; список готовых
  обзоров — суфлёр, материалы и пост: посмотреть, скопировать, скачать.

### «Дайджест новостей» — вердикт судьи

Шаг «Текст» показывает вердикт судьи (готово / с оговорками / не готово) и
`review.md`. С «не готово» шаг «Публикация» ждёт галочку «Опубликовать
несмотря на вердикт» — как `FORCE=1` у narrator.

### «Пост в канал» — новый сценарий `/studio/?scenario=post`

Свой постер, свой mp3 (или озвучка текста) и подпись → в каналы. Шаги
«Текст» (подпись, счётчик 1024), «Постер» (загрузить), «Озвучка»
(загрузить или озвучить), «Видео» (постер под звук с оформлением),
«Публикация». Лишние шаги сценария пропускаются.

Всем сценариям: у Telegram-публикации вид поста — «видео одним постом» или
«картинка с подписью, затем аудио» (`NEWS_POST=photo`).

### «Каналы» — новая вкладка `/channels/`

- Каналы публикации: список, добавить, править, убрать; импорт из
  `telegram_tems.md`. Это тот же `channels.json`, что в шаге «Публикация».
- Бот: найден ли токен, имя бота.
- Подписчики бота: кто, с какого дня, активен ли; «Обновить»; переключатель
  «Принимать подписки» (фоновый `narrate bot serve`).

### «Обновления» — модели озвучки

Секция «Модели озвучки»: что лежит на диске; «Скачать основные (~3,7 ГБ)»,
«Скачать для сравнения» (выбор моделей mlx), «Перенести из ~/.cache» —
задачи с логом.

### Сценарии — недостающие сцены

В слайды добавляются сцены «глава» (крупный заголовок раздела), «код»
(строки набираются) и «итог» (пункты с галочками), а наверху кадра в видео
по статье — полоса прогресса с названием главы.

## Проверка

- `make check` в `app/platform` (unittest на фейках, линт JS) и в
  `app/narrator` (ruff, pytest).
- Новые вкладки и мост покрыты тестами через HTTP на фейковом движке.
- Ручная проверка — в браузере на `make demo`.

## Что сознательно не делаем

- Не переносим Remotion и Slidev — их результат делают сценарии платформы.
- Не переносим старый `narrate ui` — платформа его заменяет.
