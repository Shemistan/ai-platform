# Вкладка «Монтаж»: своя запись → ролик для YouTube (PRD-020, PRD-021, PRD-022)

## Зачем

Обзоры недели и месяца автор снимает сам, по суфлёру. Монтировать нечем:
паузы, оговорки, дубли, переключение «голова / экран» — руками в монтажке.
Идея — из ролика Н. Велса «Claude Code только что изменил монтаж видео
навсегда» (17.10.2026) и открытого скилла browser-use/video-use: модель не
смотрит видео, а **читает** его — расшифровку со временем каждого слова, — и
по ней решает, что вырезать; ffmpeg режет; результат перепроверяется
повторной расшифровкой. Правки человека копятся в правилах, чтобы следующий
ролик не повторял старых ошибок. Моушн-графика — HTML + GSAP через HyperFrames.

Успех: автор загружает сырую запись (и запись экрана), подтверждает план и
получает mp4 без пауз и оговорок, с переключением планов, который можно
сразу заливать на YouTube.

Цели:
- отдельная вкладка «Монтаж» со своим списком роликов (не доска «Выпуски»);
- точная локальная расшифровка: три модели на SSD и их сравнение на
  русском тексте с английскими словами;
- план правок — человеку на подтверждение; самопроверка после сборки;
- правила монтажа, которые пополняются из правок;
- моушн-вставки поверх готового ролика.

Не цели (v1): размытие областей кадра по просьбе в кадр (план сообщает
«не умею» в заметках), вертикальные шортсы из монтажа (отдельная задача),
мультикамера больше двух источников, музыка, облачная расшифровка.

Антицели: вырезать смысл (лучше оставить лишнюю паузу, чем съесть слово);
резать посреди слова; «монтаж» без возможности посмотреть и поправить план.

## Входы

- **«Голова»** — обязательно: mp4/mov/webm, звук — голос автора.
- **«Экран»** — по желанию: запись экрана той же сессии. Синхронизация —
  моё решение: если у «экрана» есть звук, сдвиг ищется взаимной корреляцией
  огибающих звука (точность ~10 мс, окно поиска ±60 с); звука нет — старт
  совпадает. Сдвиг виден и правится вручную в карточке ролика.
- Название, модель расшифровки, термины (английские слова и имена для
  подсказки модели), параметры: собирать без подтверждения, субтитры в кадре,
  цветокоррекция, моушн-графика.

Размер загрузки — до `AIP_MONTAGE_MAX_GB` (16 ГБ) на файл, потоком на диск.

## Конвейер

```
загрузка → звук (wav 16 кГц) → расшифровка (ASR, GPU-замок) → тишина (silencedetect)
  → план (LLM: вырезки и планы по индексам слов) → ждёт человека
  → сборка (посегментно ffmpeg, кэш сегментов) → проверка (тех. + повторная ASR + LLM)
  → до 2 кругов исправлений → моушн-графика (HyperFrames) → готово
```

### Расшифровка (PRD-020)

Каталог `montage/asr.py`; веса — `<AIP_MODELS_DIR>/asr/<имя репозитория>`,
ревизии закреплены (SEC-011):

| id | модель | репозиторий | размер |
|---|---|---|---|
| `whisper-large-v3-turbo` (по умолчанию) | Whisper Large V3 Turbo | mlx-community/whisper-large-v3-turbo | 1,5 ГБ |
| `whisper-large-v3` | Whisper Large V3 | mlx-community/whisper-large-v3-mlx | 2,9 ГБ |
| `qwen3-asr-1.7b` | Qwen3-ASR 1.7B + Qwen3-ForcedAligner 0.6B | mlx-community/Qwen3-ASR-1.7B-bf16, …ForcedAligner-0.6B-bf16 | 3,8 + 1,7 ГБ |

- Запуск — mlx-audio 0.5.8 (`[stt]`) в своём окружении
  `~/.local/share/montage/mlx-audio-0.5.8/.venv` (ставит `make models M=…`,
  путь — `AIP_MONTAGE_ASR_PYTHON` в `local.mk`). Воркер
  `montage/asr_worker.py` — самостоятельный скрипт (платформу не импортирует):
  wav, модель, точки разреза → JSON слов `{w, s, e}`.
- Звук режется на куски ≤ 5 мин по тишине (у выравнивателя Qwen предел
  ~5 мин); прогресс — после каждого куска.
- Whisper даёт время слов сам (`word_timestamps`); Qwen3-ASR даёт текст,
  время слов — Qwen3-ForcedAligner (он выкидывает знаки препинания — слова
  сопоставляются с текстом ASR по порядку, пунктуация возвращается).
- Термины проекта и общий словарь из правил идут в `hotwords`.
- **Сравнение моделей** — `make asr-compare REC=<запись> REF=<эталон.md>`
  (эталон — `teleprompter.md`, по нему читали): по каждой установленной
  модели — WER, доля верно узнанных латинских слов, доля слов, попавших в
  тишину (грубая мера точности времени), скорость (× реального времени).
  Отчёт — таблица в терминал и `asr-compare.md` рядом с записью. Идёт в
  терминале человека: в песочнице агента нет Metal.

### План (LLM)

Модель видит расшифровку фразами: `[номер первого слова] 12.3 текст …`,
паузы — `(пауза 1.8 с)`; правила монтажа (`montage/assets/rules.md`) и
выученные правила (`lessons.md`); есть ли «экран». Отвечает JSON:

```json
{"cuts": [{"from": 120, "to": 131, "kind": "retake", "reason": "дубль: фраза сказана заново"}],
 "layout": [{"from": 0, "layout": "head"}, {"from": 340, "layout": "split"}],
 "notes": "просьбу размыть ключ не выполнил — не умею"}
```

- Индексы слов, а не секунды: модель не считает время, время берётся из
  расшифровки.
- `kind`: `filler` (паразит), `retake` (дубль, оставляем последний),
  `slip` (оговорка, обрыв), `command` (просьба в кадр — сама команда
  вырезается, её действие выполняется: «вырежи это» → вырезка, «покажи
  экран» → план), `extra` (лишнее по смыслу).
- Паузы — без LLM, детерминированно: пауза длиннее `max_pause` (0,6 с)
  ужимается до `keep_pause` (0,25 с), начало и конец ролика обрезаются.
- Границы вырезок ставятся в тишину между словами (середина тишины из
  `silencedetect`, иначе середина промежутка), никогда внутри слова;
  сегменты короче 0,3 с сливаются с соседями.
- Планы (`layout`): `head` — голова на весь кадр, `screen` — экран,
  `split` — экран и голова кружком в углу. Без «экрана» — только `head`.

### Подтверждение

Расшифровка показывается текстом, вырезки — зачёркнутыми и подписанными
(вид и причина), кликом вырезка снимается или ставится обратно; план кадра
меняется у фразы. Сводка «было 25:10 → станет 21:40, вырезок 43». Кнопки:
«Собрать», «Переделать с замечанием» (текст → LLM переделывает план и
формулирует правило в `lessons.md`). Флаг «собирать без подтверждения» —
сразу дальше.

### Сборка

- Каждый сохранённый кусок — отдельный ffmpeg (`-ss/-to` до `-i`, точная
  перемотка с перекодированием): раскладка планов в 1920×1080, 30 fps,
  цветокоррекция головы (`none` / `punch` / `warm`), затухание звука 30 мс
  на склейках, libx264 + AAC 48 кГц. Имя файла — хэш параметров: пересборка
  после правки берёт неизменённые куски из кэша.
- Склейка — concat без перекодирования; финальный проход: громкость
  `loudnorm` −14 LUFS (YouTube), субтитры в кадре (ASS, по 2–4 слова) —
  если включены и в ffmpeg есть `subtitles`, моушн-вставки, метка ИИ не
  ставится (это съёмка человека, ИИ только резал). Рядом — `subtitles.srt`
  для загрузки на YouTube.

### Самопроверка

1. Техника: длительность ≈ сумме кусков, есть звук и видео, `silencedetect`
   на результате — паузы длиннее `max_pause + 0,3 с`.
2. Повторная расшифровка результата той же моделью → LLM ищет оставшиеся
   оговорки, повторы, оборванные слова (индексы слов результата).
3. Найденное переводится в время исходника по таблице сегментов,
   становится вырезками, ролик пересобирается (из кэша) — не больше двух
   кругов. Всё найденное и сделанное — в `check.json` и в карточке.

### Моушн-графика (PRD-022)

- LLM по расшифровке готового ролика предлагает вставки: не чаще раза в
  30 с, только где они добавляют смысл (цифра, список, термин, заголовок
  главы), — по шаблонам `title`, `lower_third`, `stat`, `list`, `quote`
  с полями и временем.
- Шаблоны — наши HTML + GSAP (разметка в `motion.py`, стили — `assets/motion/style.css`),
  цвета и шрифт из дизайн-системы; HyperFrames (`@hyperframes/cli` 0.8.172, Apache-2.0,
  Node 22+) рендерит каждую вставку в прозрачный MOV (ProRes 4444),
  финальный проход накладывает их `overlay` по времени.
- Нет HyperFrames или Node 22 — шаг пропускается, причина в карточке.

## Правила и уроки

- `montage/assets/rules.md` — базовые правила монтажа (в репозитории):
  что резать, что оставлять, как выполнять команды в кадр, критерий
  готовности. `assets/motion-rules.md` — правила вставок.
- `<AIP_DATA_DIR>/montage/lessons.md` — выученные правила и словарь
  терминов; правятся во вкладке («Правила монтажа»); замечание человека
  добавляет туда обобщённое правило с датой.

## Устройство

`aiplatform/montage/` — модуль как «Диктор»:

| Файл | Что |
|---|---|
| `config.py` | `AIP_MONTAGE_*`: окружение ASR, каталог весов, LLM, HyperFrames, лимит загрузки |
| `asr.py` | каталог моделей, «установлена», argv воркера, разбор вывода |
| `asr_worker.py` | воркер в окружении mlx-audio |
| `transcript.py` | слова, тишина, фразы для LLM, сопоставление времён |
| `edl.py` | вырезки и планы → сегменты; карта «результат → исходник» |
| `plan.py` | промпты и разбор ответов LLM (план, проверка, замечание, вставки) |
| `render.py` | argv ffmpeg: сегмент, склейка, финальный проход, субтитры |
| `sync.py` | сдвиг «экрана» по звуку |
| `motion.py` | шаблоны вставок, HyperFrames |
| `projects.py` | проекты на диске, очередь, конвейер |
| `compare.py` | сравнение моделей (`make asr-compare`) |
| `service.py` | HTTP `/api/montage/…` |

Данные: `<AIP_DATA_DIR>/montage/projects/<id>/` — `project.json`,
`sources/`, `audio.wav`, `words.json`, `plan.json`, `segments/`,
`output.mp4`, `subtitles.srt`, `check.json`, `motion/`; `lessons.md`.

Фейки: `fake_asr.py` (слова по длительности звука, с паузой и
повтором), `fake_hyperframes.py`; задачи `montage_*` в `fake_llm.py`.

## Что решает строитель

Вёрстку вкладки, тексты подсказок, точные параметры фильтров цветокоррекции
и стиля субтитров, формулировки промптов — в рамках этих правил.
