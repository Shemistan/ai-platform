# Студия: без лимита слайдов, динамические слайды вперемешку с картинками

## Зачем

Сейчас план видео — не больше 20 слайдов, и слайд привязан к абзацу. На
десятиминутной статье слайд висит по 30–40 секунд: картинка с медленным
наездом и три тезиса. Внимание уходит.

Хотим:

1. **Без лимита** на число слайдов и картинок.
2. **Динамические слайды** вперемешку со сгенерированными картинками: график
   рисуется, число набегает, схема собирается по шагам, сравнение «было /
   стало», цитата появляется по словам. Набор сцен — как у фильма narrator
   (`07_offline_text-to-word/tools/film`, Remotion).
3. **Ритм 3–5 секунд**: каждые 3–5 секунд в кадре что-то меняется — либо
   новый слайд, либо на слайде появляется следующий элемент, либо у картинки
   меняется план (другой наезд или панорама).

## Решение

### План слайдов

- `MAX_SLIDES` убран. Верхней границы нет; в промпт уходит ориентир — сколько
  слайдов нужно на длину озвучки, чтобы слайд держался 3–6 с.
- Слайд привязан к фразе: `para` — абзац (как раньше), `sent` — номер фразы в
  абзаце (по умолчанию 0). Старые планы без `sent` читаются как раньше.
  В промпте фразы внутри абзаца пронумерованы: `[3] (0) … (1) …`.
- У слайда есть `kind`:

  | kind | что на экране | данные |
  |---|---|---|
  | `image` | сгенерированная картинка, заголовок и тезисы | `image_prompt`, `video_prompt` |
  | `bullets` | заголовок, пункты выезжают по одному | `bullets` |
  | `stat` | крупное число набегает от нуля, полоса для процентов | `value`, `prefix`, `suffix`, `label` |
  | `chart` | столбцы растут / линия рисуется по точкам | `chart` (`bar`/`line`), `unit`, `data[{label, value}]` |
  | `flow` | шаги схемы появляются по очереди, стрелки между ними | `steps` |
  | `compare` | две колонки, пункты по очереди, «vs» | `left`/`right` `{title, items}` |
  | `quote` | цитата проявляется по словам | `text`, `author` |

  Слайд без `kind` — `image`, если есть `image_prompt`, иначе `bullets`
  (так читаются старые планы). Картинки рисуются только для `image`;
  ролики — как раньше, у `image`-слайдов и не больше `MAX_CLIPS`.
- Промпт просит чередовать: после картинки — динамический слайд, две
  картинки подряд — редко; данные для графиков и чисел — только из текста.

### Ритм внутри слайда (рендер гарантирует сам)

Даже если модель сделала длинный слайд, рендер не даёт кадру стоять дольше
`BEAT_S` (4 с):

- `image`: длинный слайд режется на планы по ~4 с, у каждого своё движение
  камеры (наезд, отъезд, панорама влево/вправо); тезисы появляются по одному,
  растянуто на длину слайда.
- динамические: элементы (пункты, столбцы, шаги, слова цитаты) появляются
  равномерно по длине слайда, шаг не больше `BEAT_S`. Когда всё показано, а
  слайд ещё идёт — подсветка переходит к следующему элементу каждые `BEAT_S`.

### Рендер

Без новых зависимостей: тот же ffmpeg. `drawtext` анимирует x/y/alpha
покадрово (выезд, проявление). Выражения `drawbox` ffmpeg покадрово не
считает, поэтому рост столбцов, полосы и линия графика — ступенями: каждая
ступень — `drawbox` с `enable='between(t,…)'`, 12 ступеней на рост.
Набегающее число — то же: ~20 кадров текста, каждый в своём окне времени.
Фон динамических слайдов — тёмный с акцентной полосой, как у слайда без
картинки; плашка канала и пометки о запрещённых организациях — как у
остальных слайдов.

## Не делаем

- Remotion/Node в платформе — новая тяжёлая зависимость ради того, что
  ffmpeg умеет сам.
- Переходы-склейки между слайдами (crossfade): каждый слайд — отдельный
  клип, склейка без перекодирования остаётся.
- Код-сцену (`code`) фильма narrator — для статьи и дайджеста не нужна.

## Как проверяем

- Юнит-тесты: разбор плана (`sent`, `kind`, данные сцен, без лимита),
  длительности по фразам, расписание появления (шаг ≤ `BEAT_S`), планы
  картинки.
- Рендер каждого `kind` на четвертинке кадра в тестах (ffmpeg есть на машине)
  и сборка демо-проекта целиком: кадры глазами.
