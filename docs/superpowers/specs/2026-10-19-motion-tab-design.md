# Вкладка «Моушн»: агенты придумывают и рисуют анимации к готовому видео (PRD-026)

## Зачем

Автор ведёт технический YouTube-блог: Go, сети, устройство технологий. В кадре
он объясняет механизм, и в этот момент зрителю нужна анимация, которая его
показывает. Например, горутина кладёт значение в буферизованный канал (гофер,
буфер с ячейками, блокировка на полном буфере), или HTTP-запрос спускается по
слоям HTTP → TCP → IP → Ethernet и обрастает заголовками.

Моушн «Монтажа» (PRD-022) — пять текстовых шаблонов, вшитых в ролик: механизм
ими не объяснить, а исходник меняется. Здесь всё наоборот: исходное видео не
трогается, на выходе — N отдельных роликов-анимаций с таймкодами. Автор сам
ставит их в своё монтажное приложение.

## Решения человека

- Вход: готовое видео (загрузка). Проверочный пример — 29-минутный ролик из «Монтажа».
- Расшифровка с таймкодами — о чём речь и где.
- Над смыслом думает команда агентов, у каждого своя роль и точка зрения:
  что и где вставить, как задизайнить, каких персонажей и объекты взять, как
  поставить сцену.
- Анимации делаются, оригинал не меняется, на выходе — N моушн-роликов и
  моменты, куда их ставить.
- «Делай всё сам» — без согласований по ходу; человек смотрит результат.

## Цели

1. Проект: видео загружается или берётся готовым роликом из «Монтажа» (без
   копии на 10 ГБ — жёсткая ссылка; расшифровка пересчитывается из монтажной
   без повторного Whisper).
2. Расшифровка: те же модели и воркер, что в «Монтаже» (`montage/asr.py`), под GPU-замком.
3. Команда агентов — отдельные вызовы `claude -p` (ADR 0006), у каждого своя
   роль, промпт и формат ответа:
   - **Редактор смысла** читает всю расшифровку и выбирает моменты, где
     автор объясняет механизм, структуру, процесс или сравнение и картинка
     поможет больше слов. Отдаёт интервал по индексам слов, суть и зачем.
   - **Дизайнер** задаёт единый визуальный язык выпуска: палитру, шрифты,
     фон, правила размещения рядом с говорящим, набор персонажей и объектов
     (гофер, пакет, сервер, буфер…) с описанием, как их рисовать в SVG.
   - **Режиссёр** на каждую сцену: формат (весь кадр / половина кадра / нижняя
     треть), длительность, раскадровка битами с привязкой к словам автора
     (появилось — когда он это говорит), камера, вход и выход.
   - **Технический редактор** сверяет раскадровку с предметом: порядок слоёв,
     семантику канала, термины. Исправляет или снимает сцену.
   - **Аниматор** пишет композицию HyperFrames: HTML, CSS (SVG-персонажи) и
     GSAP-таймлайн по раскадровке. Тайминги битов приходят уже в секундах.
     Если рендер упал, аниматор получает ошибку и чинит (одна попытка).
   Сцены после редактора идут параллельно (`AIP_MOTION_PARALLEL`, по умолчанию 3).
4. Рендер: HyperFrames → MOV ProRes 4444 с альфой (сцена «на весь кадр»
   рисует свой фон). Частота кадров — как у исходника (до 60), размер —
   1080p или как у исходника.
5. Превью для человека: MP4 720p — кусок исходника с наложенной анимацией,
   видно, как это ляжет. Плюс кадр-обложка.
6. Результат: список сцен с таймкодом `ЧЧ:ММ:СС:КК`, превью, что показывает,
   формат. Скачать по одной или zip-пакетом: `NN_ЧЧ-ММ-СС_<slug>.mov`,
   `timecodes.csv`, `timecodes.txt`, `scenes.json`.
7. Правка сцены: замечание текстом → режиссёр, техред, аниматор и рендер
   заново только для неё. Сцену можно выключить из пакета. Свою сцену можно
   добавить: «на 12:30 покажи, как работает select».

## Не цели

- Звук в анимациях. Под речью автора музыка и SFX мешают; ролики немые.
  (Скилл vizavi-motion по умолчанию делает звук; здесь решение обратное.)
- Вшивать анимации в исходник или собирать монтажный проект (FCPXML, EDL).
  Только CSV и TXT с таймкодами.
- Автоматическая визуальная проверка кадров моделью: `claude -p` без
  инструментов (SEC-004) картинок не видит. Проверка — техническая
  (рендер, длительность, альфа), визуально — человек по превью.
- 3D, генеративные картинки и видео моделями «Фото»/«Видео» — только вектор
  и типографика в HTML.

## Анти-цели (провал, даже если «работает»)

- Анимация врёт о предмете: пакет идёт снизу вверх при отправке, в
  небуферизованный канал «кладётся» без получателя.
- Сцена не о том, что говорится в эти секунды, или опаздывает к словам.
- Слайды с текстом вместо механизма: анимация должна показывать действие.
- Сцены каждые 20 секунд: зритель приходит к автору, не к мультфильму.
- Композиция тянет сеть, кроме GSAP с jsdelivr, или выполняет чужой код в окне платформы.

## Ограничения

- Данные — файлы (ADR 0007): `AIP_DATA_DIR/motion/projects/<id>/`.
- Один воркер на модуль (как «Монтаж»), очередь проектов.
- HyperFrames и LLM — те же команды, что в «Монтаже» (`AIP_MONTAGE_HYPERFRAMES_CMD`, `AIP_LLM_CMD`).
- Код аниматора — недоверенный: в композиции CSP без сети (кроме GSAP),
  превью HTML в UI — `iframe sandbox="allow-scripts"` без same-origin.
- Фейки: `AIP_BACKEND=fake` — fake_llm отвечает за каждую роль,
  fake_hyperframes рисует MOV нужного размера.

## Как устроено

```
motion/
  config.py    MotionConfig: каталог, параллельность, команды из montage.config
  agents.py    роли: промпты, разбор ответов, сборка композиции, проверки
  scenes.py    время: слова ↔ секунды, таймкоды, пакет (csv/txt/zip)
  source.py    импорт из «Монтажа»: жёсткая ссылка output.mp4, слова результата по edl
  projects.py  MotionProjects: хранение, очередь, конвейер, этапы (montage/stages.py-стиль)
  service.py   HTTP /api/motion/
  assets/      правила ролей (rules-*.md), каркас композиции
static/motion/ index.html, app.js, style.css
```

Этапы действия `make`: звук → паузы → расшифровка → редактор → дизайнер →
режиссёр → техред → аниматор → рендер → превью. Действие `scene`: режиссёр →
техред → аниматор → рендер → превью для одной сцены.

`project.json`: `id, title, status, options{model, max_scenes, size, terms},
source{duration,width,height,fps,ext}, origin{montage: pid}?, transcript,
design, scenes[{n, id, at, end, title, concept, layout, status, enabled,
error, files…}], stages, history, log`.

Файлы проекта: `source.<ext>`, `audio.wav`, `words.json`, `moments.json`,
`design.json`, `scenes/<id>/{storyboard.json, index.html, scene.mov,
preview.mp4, poster.jpg}`, `package.zip`.

## Оставлено строителю

Формулировки промптов ролей, лимиты (длительность сцены 4–20 с, не ближе
30 с между сценами, 1 сцена на ~2–3 минуты по умолчанию), имена этапов,
раскладка UI в стиле «Монтажа».
