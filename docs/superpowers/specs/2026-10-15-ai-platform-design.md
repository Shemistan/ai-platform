# AI Platform: фото, видео, аудио и сценарии в одном сервисе

## Зачем

Сейчас три отдельных сервиса, каждый со своим портом, очередью и страницей:

| Сервис | Репозиторий | Что умеет |
|---|---|---|
| photogen | `11_photo_generator` | txt2img, правка фото (img2img), inpaint (удалить/заменить объект), outpaint |
| videogen | `10_video_generator` | видео по промпту, по ключевым кадрам, «живое фото» (±4 с вокруг кадра) |
| narrator | `07_offline_text-to-word` | озвучка текста (локальные TTS), дайджест новостей, пост в Telegram |

Нужен один сервис **ai-platform**: вкладки «Фото», «Видео», «Аудио» и вкладки
бизнес-сценариев — «Дайджест новостей» и «Видео по статье».

**Что сказал человек.** Вкладки по типам генерации с их нынешним функционалом;
сценарии дайджеста и статьи; шаги: (1) текст, (2) промпт постера + галочка
«локальная модель / загружу сам», (3) промпты картинок, (4) динамичные слайды,
(5) озвучка и сборка, (6) выбор канала публикации; галочка «шортс» —
вертикальное видео для YouTube Shorts / TikTok / Reels.

**Допущения (решены без вопросов, по регламенту автономности).**

- Работаем на том же Mac (Apple Silicon), что и исходные сервисы; модели
  локальные, ставятся их же `setup-model.sh` / `make models`.
- Исходные репозитории остаются как есть; платформа — новый код, в который
  перенесена логика photogen/videogen, а озвучка и сбор новостей вызываются
  через CLI narrator (его зависимости — torch, f5-tts — в платформу не тащим).
- Шортс — не обрезка длинного видео, а отдельный короткий сценарий (~45–60 с)
  по тому же материалу: свой текст, своя озвучка, вертикальный рендер 1080×1920.
- Публикация автоматом — Telegram (Bot API). YouTube / TikTok / Instagram —
  «пакет для ручной загрузки» (mp4 + заголовок + описание), потому что их API
  требуют OAuth-приложений, которых нет. Интерфейс публикатора позволяет
  добавить их позже.

## Критерии успеха

1. `make demo` поднимает платформу без моделей и сети: все вкладки работают
   на фейковых бэкендах, сценарий статьи проходит от текста до mp4 (16:9 и,
   с галочкой, 9:16).
2. Функционал вкладок «Фото» и «Видео» не меньше исходных сервисов (те же
   режимы, модели, параметры, история, отмена).
3. В один момент в памяти одна тяжёлая модель: фото, видео, аудио и шаги
   сценариев делят один GPU-замок.
4. Каждый шаг сценария виден, редактируем и перезапускаем по отдельности;
   «Запустить всё» идёт до первого шага, которому нужен человек.
5. `./check` зелёный: юнит- и HTTP-тесты на фейковых бэкендах.

## Подходы

| | Подход | Плюсы | Минусы |
|---|---|---|---|
| A | Шлюз: общая страница + прокси на три работающих сервиса | быстро, код не трогаем | три процесса делят GPU без координации → OOM; сценарии всё равно надо писать; три запуска вместо одного |
| **B** | **Монолит: перенести код photogen/videogen в один пакет, общий GPU-замок, narrator — как CLI-инструмент** | один процесс и порт, один замок на GPU, общий движок задач для сценариев | перенос ~2 тыс. строк; исходники и платформа разойдутся |
| C | Переписать всё на FastAPI + SPA | «современно» | новый стек без выгоды, переписывать проверенный UI |

**Выбран B.** Исходники маленькие и на одном стеке (Python stdlib, ванильный
JS), поэтому перенос дешёвый, а общий замок GPU и единая очередь — то, чего
подход A не даёт. Стек сохраняем: stdlib-сервер, без сборки фронтенда, тесты
на `unittest`, фейковые бэкенды.

## Архитектура

```
app/platform/                     # сервис; ./check зовёт его make check
  aiplatform/
    config.py                     # AIP_* переменные: порт, данные, бэкенды, пути
    server.py                     # один ThreadingHTTPServer, маршруты по префиксу
    core/                         # общее
      runner.py                   # subprocess с отменой и построчным выводом
      uploads.py                  # загрузки картинок / аудио
      gate.py                     # GPU-замок: одна тяжёлая модель за раз
      http.py                     # Request/HttpError/ответы — для всех вкладок
    photo/                        # перенос photogen: models, params, mflux, flux2, jobs
    video/                        # перенос videogen: models, timeline, living, ltx, wan, jobs
    audio/                        # озвучка через narrator CLI: voices, jobs
    studio/                       # сценарии
      pipeline.py                 # проект сценария: шаги, статусы, артефакты, запуск
      steps.py                    # реализации шагов
      llm.py                      # LLM через CLI (`claude -p`), фейк для демо
      news.py                     # сбор новостей и пересказ через narrator
      slides.py                   # план слайдов → кадры ffmpeg (Ken Burns + текст)
      assemble.py                 # склейка mp4: постер, слайды, звук; 16:9 и 9:16
      publish.py                  # каналы: Telegram, ручной пакет
    fakes/                        # фейковые CLI моделей, TTS, LLM, новостей
    static/                       # общая шапка-вкладки + страница каждой вкладки
  tests/
```

### Вкладки и адреса

| Вкладка | Страница | API |
|---|---|---|
| Фото | `/photo/` | `/api/photo/...` — как в photogen |
| Видео | `/video/` | `/api/video/...` — как в videogen |
| Аудио | `/audio/` | `/api/audio/...` |
| Дайджест | `/studio/?scenario=digest` | `/api/studio/...` |
| Видео по статье | `/studio/?scenario=article` | `/api/studio/...` |
| (корень) | `/` → `/photo/` | `/api/config` — что доступно |

Каждая вкладка — своя страница с общей шапкой навигации (`nav.js`). Так UI
photogen/videogen переносится почти без правок: меняется только база API.

### Общий GPU-замок

`core/gate.py` — `Gate` с `hold(owner, on_wait)`: контекстный менеджер,
FIFO-очередь владельцев. Воркер каждого JobManager (фото, видео, аудио) берёт
замок вокруг запуска модели; пока ждёт — стадия «Ждёт GPU (занят: видео)».
Шаги сценариев не держат замок сами: они ставят обычные задачи в менеджеры
вкладок и ждут их, поэтому всё, что сделал сценарий, видно и в истории
вкладок. Лёгкие шаги (LLM через CLI, ffmpeg) замок не берут.

### Фото (перенос photogen)

Режимы: «С нуля» (txt2img), «Правка» (img2img), «Удалить / заменить объект»
(inpaint по маске), «Расширить кадр» (outpaint). Модели, параметры, стили,
маска-кисть, история, отмена, скачивание — как в photogen. Изменения:
префикс `/api/photo`, замок GPU, конфиг `AIP_PHOTO_*` (с откатом на старые
`PHOTOGEN_*`, чтобы `setup-model.sh` photogen продолжал работать).

Для сценариев — программный вызов `PhotoService.generate(prompt, size)` →
id задачи; ожидание `wait(job_id)`.

### Видео (перенос videogen)

Режимы: «По промпту», «По кадрам» (ключевые кадры на таймлайне), «Живое фото»
(один кадр в середине 8-секундного ролика: модель достраивает 4 с до и 4 с
после). Модели LTX-2.3 / LTX-2.5 / Wan 2.2, пресеты размеров, включая
вертикальные. Изменения те же: префикс, замок, `AIP_VIDEO_*` с откатом на
`VIDEOGEN_*`.

### Аудио

Текст → mp3. Бэкенд — CLI narrator: `narrate say FILE --engine E --voice V
--speed S --out DIR --no-verify` (команда задаётся `AIP_NARRATE_CMD`, по
умолчанию `../07_offline_text-to-word/narrate`). Каталог движков и голосов —
в `audio/voices.py` (espeech, silero, supertonic, higgs…), выбор на странице.
Результат — `output.mp3`, длительность по ffprobe, проигрыватель, скачивание.
Своя очередь, тот же GPU-замок. Фейк — `fakes/fake_narrate.py` пишет mp3
нужной длины через ffmpeg (тишина + тон), без ffmpeg — wav-заглушку.

### Сценарии (studio)

Проект сценария — каталог `data/studio/<id>/` с `project.json` (настройки,
статусы шагов, лог) и файлами-артефактами. Шаг — функция
`run(project, ctx) -> None`, пишет артефакты, может вернуть «нужен человек».

| # | Шаг | Дайджест | Статья | Артефакты |
|---|---|---|---|---|
| 1 | Текст | сбор новостей и пересказ (narrator: `news collect` + агент) | текст вставлен человеком | `narration.md`, `post.md` |
| 2 | Постер | LLM пишет промпт; галочка «локальная модель» → фото-задача; иначе ждёт загрузку человеком | то же | `poster_prompt.md`, `poster.png` |
| 3 | Слайды и промпты картинок | LLM делит текст на слайды: абзац, заголовок, тезисы, промпт картинки | то же | `slides.json` |
| 4 | Картинки слайдов | галочка «рисовать картинки» → фото-задачи по промптам; иначе фон-градиент | то же | `images/NN.png` |
| 5 | Озвучка | аудио-задача по тексту, или загруженный mp3 | то же | `voice.mp3` |
| 6 | Сборка | кадры слайдов (ffmpeg: Ken Burns + появляющийся текст), тайминг по абзацам, постер 2 с в начале → `video.mp4` 1920×1080 | то же | `video.mp4` |
| 6s | Шортс (галочка) | LLM: короткий сценарий ≤150 слов → озвучка → те же слайды в 1080×1920 | то же | `short/…`, `short.mp4` |
| 7 | Публикация | выбрать каналы из списка → отправить | то же | `published.json` |

Тайминг слайдов: у слайда номер абзаца, с которого он показывается; начало
абзаца — доля слов текста до него × длительность аудио (так работает и с
чужим mp3). Длительности кадров ≥ 1,5 с.

«Динамичные» слайды делает ffmpeg без новых зависимостей: `zoompan` (медленный
наезд на картинку), затемняющий градиент, заголовок и тезисы `drawtext` с
появлением по очереди (`alpha` по времени). Шрифт — системный с кириллицей
(`/System/Library/Fonts/Supplemental/Arial Unicode.ttf`, переопределяется
`AIP_FONT`). Вертикальный режим — та же сцена в кадре 1080×1920, текст крупнее,
картинка по центру.

Запуск: «Запустить всё» — шаги по порядку в фоне, до первого, которому нужен
человек (загрузить постер, проверить текст при включённой «паузе на проверку»)
или до ошибки. Каждый шаг — «Перезапустить», артефакты-тексты правятся на
странице; правка шага сбрасывает «готово» у зависимых шагов.

LLM: `AIP_LLM_CMD` (по умолчанию `claude -p`), промпт подаётся на stdin,
ответ — текст / JSON в ```json-блоке. Фейк — детерминированный ответ по тексту.

Сбор новостей: `AIP_NEWS_CMD` — команда, которая по дате печатает путь к
каталогу выпуска narrator с `narration.md` и `post.md` (по умолчанию —
обёртка над `make news-collect news-agent DAY=…` + `./narrate news where`).
Фейк — пишет три новости-заглушки.

### Публикация

`channels.json` (путь `AIP_CHANNELS`, пример в репозитории):

```json
[{"id": "tg-news", "label": "Telegram: новости", "type": "telegram",
  "chat_id": "@my_news", "token_env": "AIP_TELEGRAM_TOKEN"},
 {"id": "yt", "label": "YouTube", "type": "manual", "format": "landscape"},
 {"id": "shorts", "label": "YouTube Shorts / TikTok / Reels", "type": "manual", "format": "vertical"}]
```

- `telegram` — `sendVideo` с подписью из `post.md` (HTML, ≤1024 знака).
  Токен — только из переменной окружения, в файлы и логи не пишется.
- `manual` — «пакет»: копия нужного mp4 + `title.txt` + `description.txt` в
  `data/studio/<id>/publish/<channel>/`, ссылка на скачивание.
- Формат канала (`landscape` / `vertical`) выбирает, какое видео уходит.

### Ошибки

- Валидация входа → 400 с понятным русским текстом (как в исходниках).
- Падение модели / CLI → задача `failed` с последней строкой лога; шаг
  сценария `failed` с тем же текстом; проект можно продолжить с этого шага.
- Нет модели / CLI / ffmpeg → `/api/config` отдаёт `problems`, вкладка
  показывает баннер «что поставить».
- Перезапуск сервиса: активные задачи и шаги → `failed` «сервис перезапущен».
- POST с чужого `Origin` → 403 (как в исходниках).

### Тесты

- Перенесённые тесты photogen/videogen (params, pipelines, timeline, ltx,
  wan, living, server) — на новых путях.
- `core`: gate (FIFO, отмена ожидания), runner.
- `audio`: build_spec, задача через фейковый narrate, HTTP.
- `studio`: тайминг слайдов, разбор JSON от LLM, фильтры ffmpeg (строка),
  сборка mp4 на фейках (если есть ffmpeg — настоящий файл и ffprobe-проверка
  размеров 1920×1080 / 1080×1920), прогон сценария «статья» целиком через HTTP,
  публикация в manual и в Telegram с подменённым HTTP-клиентом.

## Вне объёма

- Автозагрузка в YouTube / TikTok / Instagram (только пакет для ручной).
- Перенос narrator целиком (библиотека статей, обзоры недели/месяца, film с
  Remotion) — остаётся в своём репозитории.
- Авторизация пользователей: сервис локальный, слушает 127.0.0.1.
- Расписание «каждый день в N часов» — дайджест запускается кнопкой; cron
  можно добавить позже вызовом API.
