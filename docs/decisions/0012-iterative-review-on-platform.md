# 0012. Iterative Review и панель наблюдаемости — внутри «Монтажа», файлами и воркером

## Контекст

`ITERATIVE_REVIEW_SPEC.md` (вне git, корень checkout) дополняет MASTER_SPEC:
после сборки ролика — 1–5 раундов независимого ревью десятью ролями, консолидация
замечаний, план исправлений с DAG, точечная пересборка, regression gate, приём или
откат версии, ранняя остановка; плюс раздел 14 — панель наблюдаемости всего
конвейера с append-only событиями, деревом прогресса, честными процентами, SSE,
консолью логов и ресурсами.

ТЗ предполагает таблицы БД, Pydantic, WebSocket и мультимодальную модель. У
платформы: файлы (ADR 0007), stdlib HTTP и ванильный JS (ADR 0003), LLM через
`claude -p` (ADR 0006), воркер «Монтажа» с одним потоком и кэшем по хэшам
(PRD-027, ADR 0011). Мультимодальной локальной модели на машине нет
(`docs/ENVIRONMENT_AUDIT.md`): ни VLM, ни CLIP.

## Решение

Расширение `montage/`: пакет `montage/review/` (запуски, раунды, роли,
консолидация, план, исполнение, сравнение, версии) и `montage/progress.py`
(события, дерево, ETA, ресурсы, SSE). Проекция:

| ТЗ | Платформа | Почему |
|---|---|---|
| Таблицы `review_runs … revision_lineage`, `run_events`, `task_progress_snapshots`, `resource_samples` | файлы проекта: `review/runs/<id>/run.json`, `rounds/<n>/{reports,issues,repair_plan,comparison}.json`, `review/versions/V<n>/`, `events.jsonl` (seq — курсор), `progress.json`, `resources.jsonl`; схемы — `contracts/montage/review_*.schema.json`, `run_event` | ADR 0007; один пользователь и один процесс-писатель |
| Durable queue, staging-ревизия с optimistic locking, идемпотентный job id | воркер «Монтажа» (действие `review`), чекпоинт `run.json` после каждой стадии; `lock.project_updated_at` в запуске — чужая правка проекта → 409 `stale_revision`; job id = `<run>-r<n>-<stage>`: готовые артефакты стадии пропускаются при resume | тот же механизм, что у кэша сегментов и сцен |
| Мультимодальный анализ видео | честная деградация: кадры и прокси строятся настоящим ffmpeg и показываются человеку; роли «глаз» (motion, art, composition) работают по манифестам и замерам (`evidence_type: heuristic`), их отчёты помечены `degraded` и `manual_check`; `vision` в реестре возможностей — `unavailable` | ТЗ §1.4: не выдумывать визуальный анализ |
| Reviewer-агенты разными моделями | роли = адаптеры двух видов: `measure` (ffmpeg/ffprobe/манифесты — `observed_video`/`observed_audio`) и `llm` (`### task: montage_review_<role>`, одна модель `claude -p`, разные промпты); судья — отдельный промпт без самооценки исполнителя | ADR 0006 |
| Arbiter | детерминированные правила (ранг → уверенность → цена), ничья — эскалация человеку; выбор записан в `decisions.jsonl` | воспроизводимость, без второго LLM-слоя |
| WebSocket/SSE | SSE на `http.server`: `GET …/events/stream?last_event_id=`, снапшот + дельта, heartbeat, backfill по курсору, fallback — опрос | как у остальных вкладок, без зависимостей |
| GPU/VRAM-метрики, Remotion/Blender адаптеры | показываем только измеримое: loadavg, память, диск, очередь, fps ffmpeg из `-progress`; GPU — `unavailable` (без powermetrics); «GPU-минуты» бюджета = минуты тяжёлых процессов | ТЗ §14.6: не показывать то, чего нет |
| Вкладка `Review & Improve` | панели «Ревью и улучшение» и «Прогресс» внутри вкладки «Монтаж» | одна страница на весь конвейер |

Что **сознательно не делается** (в матрице приёмки — «частично» / «не реализовано»):
role-based access и redaction по ролям (один пользователь; секреты в события не
попадают по построению), несколько параллельных запусков на проект, правки звука
кроме громкости, генерация новых ассетов (`max_new_assets` считает перерисованные
сцены), изменение речи автоматически (`allow_narrative_edits` по умолчанию `false`,
и даже `true` — только через ворота).

## Последствия

- Все артефакты ревью лежат рядом с проектом, читаются после рестарта; V0 и
  исходники не перезаписываются (`versions.py` отказывает).
- События — единственный источник прогресса для UI; `project.stages` остаётся
  для совместимости и строится из того же трекера.
- Тесты — на фейках (`fake_llm` знает роли ревью и судью), ffmpeg настоящий.

## Когда пересматривать

- Появится локальная VLM с CLI — роли «глаз» получают `observed_video`.
- Второй процесс или пользователь — события в БД, очередь вне процесса.
