# 0007. Данные — файлы в `data/`, без базы данных

Записано задним числом (DX-008). Формат и версии самих файлов — отдельное
решение (BE-008); здесь только выбор «файлы вместо БД».

## Контекст

Платформа хранит: выпуски сценариев (настройки, шаги, артефакты —
картинки, аудио, видео), настройки, реестр организаций, журнал событий,
логи, pid-файлы процессов моделей. Пишет один процесс; объёмы — сотни
выпусков, и почти весь вес — медиафайлы. Человек и агенты читают и правят
данные руками (`grep` по логу, правка `settings.json`).

Альтернативы: SQLite (stdlib, но медиа всё равно на диске, а данные
делятся на два места); внешняя БД (зависимость и процесс).

## Решение

- Всё — в каталоге `AIP_DATA_DIR` (по умолчанию `data/`, демо — `data-demo/`):
  выпуск — папка `data/studio/projects/<id>/` с JSON-состоянием и
  артефактами рядом; `settings.json`, `registry.json`, `events.jsonl`
  (append-only), `logs/`, `run/`.
- Запись JSON — через временный файл и `os.replace` (атомарно на одном диске:
  `core/settings.py`, `studio/pipeline.py`); конкуренцию внутри процесса держат замки модулей.
- Резервная копия и перенос — копия каталога.

## Последствия

- Ни схемы, ни миграций БД; данные читаемы глазами и `grep`.
- Запросы «по всем выпускам» — обход папок; на сотнях выпусков это
  миллисекунды, на десятках тысяч станет заметно.
- Два процесса на одном `data/` небезопасны — тесты защищены
  `AIP_TEST_GUARD`, а сервис запускается в одном экземпляре.
- Изменение формата файла — забота кода чтения (BE-008).

## Когда пересматривать

- Нужны запросы и агрегаты по тысячам выпусков (аналитика сложнее
  `events.jsonl`).
- Появится второй процесс-писатель или несколько пользователей.
