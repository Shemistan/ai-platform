# 0005. narrator — подпроцесс: CLI для долгого, JSON-мост `bridge` для данных

Записано задним числом (DX-008); см. спеки
`2026-10-15-ai-platform-design.md` и `2026-10-16-narrator-migration-design.md`
в `docs/superpowers/specs/`.

## Контекст

narrator (`app/narrator`) — озвучка, библиотека статей, новости, бот. Его
зависимости — torch, f5-tts, MLX-движки — тяжёлые и живут в своём
uv-окружении. narrator запускают и без платформы: из терминала и агентами.
Платформе нужны и долгие действия (озвучка, сбор новостей), и данные для
страниц (голоса, статьи, источники).

Альтернативы: импортировать narrator как библиотеку (тащит torch в
stdlib-сервис, ADR 0003); HTTP-сервис narrator (второй процесс и порт).

## Решение

- Платформа не импортирует narrator, только запускает `narrate`
  подпроцессом (`app/platform/aiplatform/core/narrator.py`).
- Долгое — обычными командами (`synth`, `news collect`, `bot send`…) как
  задачи с логом и отменой.
- Данные — `narrate bridge <команда>` (`app/narrator/src/narrator/bridge.py`):
  в stdout один JSON-объект; ошибка — `{"error", "kind"}` и код 1, HTTP-код
  выбирается по `kind`. Команды и формат — `docs/api-routes.md`.
- Контракт версионирован: `bridge version` → `bridge_api`; при расхождении с
  `EXPECTED_BRIDGE_API` платформа показывает баннер, а не падает.

## Последствия

- Платформа остаётся без зависимостей; narrator обновляется и тестируется
  отдельно.
- Каждый вызов моста — запуск Python-процесса (сотни миллисекунд): мост
  только для данных страниц, не для горячих циклов.
- Формат ответа моста — публичный контракт: менять вместе с
  `BRIDGE_API` и платформой.

## Когда пересматривать

- Задержка запуска моста начнёт мешать страницам (тогда — долгоживущий
  процесс narrator с тем же JSON-контрактом).
- narrator перестанут запускать без платформы.
