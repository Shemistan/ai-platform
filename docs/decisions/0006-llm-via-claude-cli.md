# 0006. LLM через CLI (`claude -p`), а не через API-SDK

Записано задним числом (DX-008).

## Контекст

Сценариям нужен LLM: текст дайджеста, промпты постера и слайдов, выжимка,
проверка черновика. У автора есть подписка Claude Code с залогиненным
`claude`; отдельного API-ключа и SDK в проекте нет. Сервис — без
зависимостей (ADR 0003).

Альтернативы: Anthropic SDK с ключом (зависимость + ключ в конфиге, оплата
по токенам); локальная модель в процессе (память и GPU-замок).

## Решение

- `aiplatform/studio/llm.py`: промпт — на stdin, ответ — stdout, команда —
  `AIP_LLM_CMD` (по умолчанию `claude -p`). JSON из ответа достаёт
  `extract_json` (```json-блок или первый объект/массив).
- Любой CLI с тем же контрактом подходит: обёртка над локальной моделью,
  другой провайдер. В демо и тестах — фейк.
- Нет CLI — баннер «Проблемы» с подсказкой (`missing_cli`), а не падение.
- LLM-шаги GPU-замок не берут.

## Последствия

- Ни ключей, ни SDK в репозитории; авторизация — забота `claude`.
- Под launchd `PATH` короче: нужен полный путь в `AIP_LLM_CMD`.
- Нет структурированного вывода и стриминга токенов на уровне API —
  устойчивость держится на `extract_json` и проверках шагов.
- Лимиты подписки и сбои CLI видны как упавший шаг с хвостом вывода.

## Когда пересматривать

- Понадобятся tool use, структурированный вывод или контроль стоимости,
  которых CLI не даёт.
- Сервис будет работать там, где нет залогиненного `claude`.
