## Вкладки

Шапка — группами: инструменты · сценарии выпуска · материалы · обслуживание.

| Вкладка | Адрес | Что умеет |
|---|---|---|
| Фото | `/photo/` | с нуля по промпту; поправить фото; удалить или заменить объект по маске; расширить кадр; увеличить готовую картинку до 2K/4K (SeedVR2). Шесть моделей (FLUX.2, Qwen-Image, Z-Image, Krea, Ideogram) |
| Видео | `/video/` | по промпту; по ключевым кадрам на таймлайне; «живое фото» — кадр посередине, модель достраивает 4 с до и 4 с после. LTX-2.3 / 2.5, Wan 2.2 |
| Аудио | `/audio/` | текст → mp3: ESpeech, Silero, Supertonic, MLX-клоны; голос, скорость, шаги. Как прочитает модель — на лету; текст из библиотеки или md-файлов (файл с несколькими статьями — в очередь по статье); проверка распознаванием с отчётом по абзацам; образцы голосов-клонов |
| Выпуски | `/board/` | все выпуски всех сценариев: ждут тебя, идут, опубликованы, черновики; публикация в один клик; архив; «Что работает» — просмотры и прирост подписчиков по сценарию, длине и формату. В шапке — счётчик ждущих |
| Дайджест новостей | `/studio/?scenario=digest` | движок собирает новости дня, агент пишет пересказ, судья проверяет → видео и публикация; вердикт судьи «не готово» держит публикацию |
| Видео по статье | `/studio/?scenario=article` | готовая статья → видео и публикация; сцены-главы, код, итог и полоса главы |
| Пост в канал | `/studio/?scenario=post` | свой постер, свой mp3 (или озвучка подписи) и подпись → видео «постер под звук» или картинка с аудио → в каналы |
| Статьи | `/library/` | библиотека статей для прослушивания: по ссылке или своим текстом; текст для озвучки (как есть или агентом), озвучка, проверка, отправка в канал, «Сделать видео»; озвучить все новые, разослать неотправленное |
| Новости | `/news/` | источники с журналом сбора и пользой, «Собрать»; главное за день; добор упавших источников агентом; обзоры недели и месяца для YouTube (суфлёр, материалы, пост) |
| Каналы | `/channels/` | каналы публикации всех сценариев; бот движка; подписчики бота и приём подписок |
| Обновления | `/updates/` | новые версии пайплайнов и весов фото и видео; модели озвучки — что на диске, скачать, перенести; список запрещённых в РФ организаций для пометок в видео |
| Настройки | `/settings/` | общие настройки платформы: какие модели фото и видео, движки озвучки и голоса включены; дайджест по расписанию и уведомления; обновление отклика; уборка старых данных |

Тяжёлые модели идут по одной: у вкладок общий GPU-замок. Пока одна модель
работает, задача другой вкладки ждёт со статусом «Ждёт GPU (занят: …)», а
шапка показывает, кто занял GPU.

## Сценарии: как устроен выпуск

Выпуск — цепочка шагов. Каждый шаг виден на странице, его результат можно
поправить руками, заменить своим файлом или перезапустить. «Запустить всё»
выполняет каждый шаг, для которого всё готово. Шаг, который ждёт твоих
файлов (постер, картинки, видео, озвучка), держит только то, что без них
не собрать: остальное идёт дальше. Файлы можно класть, пока выпуск работает;
как только загружен последний недостающий, сборка продолжается сама. После
«Остановить» выпуск сам не продолжается — до следующего «Запустить всё».

| # | Шаг | Что делает | Можно вручную |
|---|---|---|---|
| 1 | Текст | дайджест: движок собирает новости, агент пишет пересказ, судья проверяет выпуск — его вердикт и отчёт видны в шаге; статья: вставленный текст; пост: подпись (и текст для озвучки) | править текст; галочка «пауза после текста» |
| 2 | Промпт постера | дайджест: промпт обложки из выпуска narrator (`image_prompt.md`: гофер в сцене по событиям дня и заголовки на картинке), нет его — LLM пишет такой же; статья: LLM пишет промпт обложки | править, скопировать |
| 3 | Постер | дайджест: по умолчанию «загружу свой» — обложку делают в ChatGPT по промпту и перетаскивают сюда или кладут `cover.*` в каталог выпуска narrator (подхватится сама, после правки — «Перезапустить шаг»); иначе галочка «локальная модель» → задача во вкладке «Фото» (у дайджеста квадрат 1024×1024); иначе промпт и окно, куда перетащить картинку, сделанную во внешней модели | загрузить свою |
| 4 | Слайды | LLM делит текст на слайды без ограничения числа — примерно по слайду на «время слайда» озвучки (настройка, ~4–12 с; по умолчанию 6 с, у дайджеста 8 с) и с текстом, который за это время читается, начало — абзац и фраза. Слайды двух сортов вперемешку: картинка (заголовок, тезисы, промпты картинки и видео) и динамические сцены, которые рисует сборка: пункты, крупное число, график столбцами или линией, схема из шагов, сравнение «было / стало», цитата, глава, код (строки набираются), итог с галочками; плюс название и подпись к посту. Есть главы — сверху видео полоса прогресса с названием текущей главы | править JSON |
| 5 | Картинки | только для слайдов-картинок: «локальная модель» → задачи во вкладке «Фото»; «сделаю сам» → у каждого такого слайда промпт и окно справа, куда перетащить готовую картинку из внешней модели. На видео картинка — фон, длинный слайд режется на планы до 5 с с разным движением камеры (наезд, панорама, отъезд). Настройка «увеличить» — каждую сгенерированную картинку и постер до 2K или 4K (SeedVR2); смена только увеличения не перерисовывает картинки. Можно выключить — будет градиент | перетащить свою картинку любому слайду |
| 6 | Ролики | галочка «добавить ролики»: LLM выбирает до 3 самых динамичных слайдов и пишет им промпт видео — там вместо картинки ролик 5 с (крутится по кругу без своего звука). «Локальная модель» → задачи во вкладке «Видео» (LTX / Wan, 704×448); «сделаю сам» → промпт и окно для готового ролика (MP4, MOV, WebM), «Продолжить без недостающих» — собрать с тем, что есть | перетащить свой ролик |
| 7 | Озвучка | задача во вкладке «Аудио» или свой mp3 (например, из Gemini TTS) | загрузить свой |
| 8 | Видео | ffmpeg (кадр 16:9 или как постер — см. ниже): постер 2 с (с оформлением — 3 с, см. ниже), затем слайды под фразы озвучки; слайд не сменится, пока не прочитан (см. ниже). Ритм: каждые 3–5 с в кадре что-то меняется — новый слайд, следующий элемент сцены (пункт, столбец, шаг схемы, слова цитаты) или новый план картинки; когда всё показано, а слайд идёт, подсветка переходит по элементам каждые 4 с | — |
| 9 | Шортс 9:16 | галочка «шортс»: LLM пишет сценарий на 45–60 с, озвучка, вертикальный рендер 1080×1920 | править сценарий |
| 10 | Публикация | в выбранные каналы, после кнопки «Опубликовать» (или сразу — галочка); в Telegram с оформлением — обложка видео и миниатюра | править подпись |

У сценария «Пост в канал» шагов слайдов, картинок, роликов и шортса нет:
постер и mp3 — свои (или озвучка подписи локальной моделью), видео — постер
на всю длину звука с оформлением канала, подпись — со счётчиком 1024 знаков.

«Скорость в видео» (×0,75–×2; у дайджеста по умолчанию ×1,25, как публиковали
в narrator) ускоряет озвучку видео и шортса через `atempo` — голос не
меняет высоту, слайды подстраиваются под новую длину, а обложка и переезд
плашки идут в обычном темпе. Смена скорости пересобирает видео, озвучку — нет.

«Слайды»: «время слайда» (~4, 6, 8, 10, 12 с) — ориентир для плана, сколько
держится слайд и сколько на нём текста; смена перестраивает план. «Время на
чтение» — слайд держится не меньше, чем читается его текст: 1 с + слова на
экране (заголовок, тезисы, пункты, подписи) по 3 слова в секунду («обычно»)
или по 2 («медленно»), не больше 15 с. Следующие слайды сдвигаются и
догоняют свою фразу на длинных слайдах; отставание от озвучки от 2 с видно в
логе сборки. «Не ждать» — слайд меняется вместе с фразой, как раньше. Смена
пересобирает видео и шортс, план — нет.

«Кадр видео» в оформлении: «как постер» (ширина 1080, пропорции картинки
обложки — квадратная обложка дайджеста даёт 1080×1080, как у narrator; не
уже 9:16 и не шире 16:9), «квадрат 1:1» или «широкий 16:9». У дайджеста по
умолчанию «как постер», у статьи — 16:9. Под кадр не 16:9 картинки слайдов
рисуются квадратными (1024×1024). Шортс всегда 9:16. Смена кадра
пересобирает только видео: готовые картинки слайдов остаются (кадр берёт их
с обрезкой), новые рисуются уже под него.

Правка результата шага сбрасывает только зависящие от него шаги: новая
картинка постера пересоберёт видео, но не тронет озвучку и слайды.

У каждого шага, в том числе в готовом выпуске, — «Параметры шага» прямо в
его карточке: у постера — режим, модель и увеличение, у картинок и роликов —
режим и модель, у озвучки — движок и голос, у сборки видео и шортса — кадр,
скорость, оформление и пометки. Поменял → «Перезапустить шаг»: шаг
пересобирается уже с новыми параметрами (`POST …/run {step, settings}`), они
же сохраняются в настройках выпуска. Шаги после него сбрасываются — их
соберёт «Запустить всё» или их собственный «Перезапустить шаг».

## Выпуски: доска, повтор, оценка, черновик

**Доска «Выпуски».** Все выпуски по группам. У ждущего — шаг и что
нужно; если ждёт только публикация и каналы выбраны — кнопка
«Опубликовать» прямо на карточке. «В архив» убирает выпуск с доски и из
списков сценария (файлы остаются, «Архив» на доске их показывает).

**Не начинать заново.** Новый выпуск по тому же дню (дайджест) или тому же
тексту (статья, пост) не создаётся молча: страница предлагает открыть
существующий или всё же создать новый. «Копия выпуска» переносит
настройки и всё готовое до сборки — попробовать другой вариант, не трогая
этот. Картинки, ролики и озвучка с теми же входами (промпт, модель,
размер, увеличение; текст, движок, голос, скорость) второй раз не
генерируются — берутся из кэша `data/studio/cache/` (клон APFS, место не
удваивается), в журнале — «из кэша». «Перезапустить шаг» кэш не читает:
им просят новый вариант.

**До запуска.** У выпуска и в форме нового выпуска — оценка времени
(картинки, ролики, озвучка, сборка — по медиане задач этой машины; без
истории — по умолчанию) и предупреждения: канал 9:16 без шортса, канал без
токена, неустановленная модель, ожидание твоих файлов, текст длиннее ~12
минут. Публикация сначала проверяет все выбранные каналы и только потом
отправляет: при ошибке не уходит никуда.

**Черновик.** Галочка «Черновик» в настройках выпуска: без картинок и
роликов, кадр вполовину — быстро посмотреть структуру и ритм. «Сделать
чистовик» снимает её и дособирает выпуск; озвучка и слайды не
переделываются. Для длинной статьи — «Разбить на серию» (по заголовкам `#`
и абзацам, части по ~1000 слов, исходный выпуск — в архив) и «Сделать
выжимку» (LLM пишет текст на 5–8 минут — новый выпуск).

**Расписание и уведомления** («Настройки»). Дайджест сам в заданное время —
за вчера или за сегодня; если платформа была выключена, он соберётся при
запуске в тот же день. Уже собранный или убранный в архив день не
пересоздаётся. Уведомления: выпуск ждёт тебя, упал или опубликован — в
Telegram, если в «Настройках» указан твой чат (id или @username; пишет бот
каналов, токен — как у каналов; сначала напиши боту `/start`), и на Mac
системные (osascript), своя команда — `AIP_NOTIFY_CMD` (заголовок — первая
строка stdin). Указал чат — уведомления включаются сами. «Проверить
уведомление» шлёт тестовое и показывает ошибку, если не дошло; итог каждой
доставки — в логе процесса. Журнал — `data/notifications.log` (с ротацией).

**Отклик.** При публикации в Telegram запоминаются id сообщения и число
подписчиков. «Обновить отклик» на доске (и раз в сутки сам) берёт
подписчиков через Bot API (`getChatMemberCount`, бот — админ канала), а
просмотры — со страницы `t.me/<канал>/<id>?embed=1`: только у публичных
каналов. У пакетов для YouTube и TikTok и у приватных каналов просмотры
вносятся руками в карточке на доске. Посты сравниваются в окнах:
просмотры за 24ч/72ч/7д (интерполяция между снимками по возрасту поста,
закрытое окно замораживается) и прирост подписчиков за сутки после поста
(до следующего поста канала, за вычетом медианного суточного прироста за
неделю без постов). «Что работает» считает только посты с закрытым окном 24ч.
Пакет для YouTube / TikTok — ещё не публикация: выпуск лежит в группе
«Выгружено, залей руками», пока на доске не нажато «Залил» со ссылкой на
ролик (`POST /api/studio/projects/<id>/uploaded`); с этого момента считается
время публикации и окна просмотров.

**Журнал событий.** `data/events.jsonl` — по строке JSON на событие выпуска:
создание и архив, старт/конец/ожидание/падение/перезапуск шага, действия
человека (с временем ожидания), отправки и снимки отклика. Поле `actor` —
system, human или scheduler. Выпуски, собранные до журнала, дописываются
бэкфиллом из их project.json, лога и published.json:
`python -m aiplatform.studio.backfill [--data data]` (повтор не дублирует).

**Уборка** («Настройки»). Сколько места у задач вкладок, выпусков, архива,
кэша и загрузок. «Убрать сейчас» (или раз в сутки) удаляет старше 7–90
дней только восстановимое: завершённые задачи «Фото», «Видео», «Аудио»
(выпуски хранят свои копии файлов), давние записи кэша и выпуски из
архива. Неархивные выпуски и идущие задачи не удаляются.

## Публикация в Telegram

Вместо `make news-publish` в narrator — кнопка «Опубликовать» в шаге
«Публикация»: рядом выбор каналов и галочка «Опубликовать повторно». Видео
уходит одним постом с подписью к посту (и обложкой, если есть оформление).
В канал, куда выпуск уже ушёл, повторно отправляется только с галочкой —
как `FORCE=1`. У дайджеста по умолчанию выбран канал новостей narrator
(`VOICE_NEWS`). Каналы можно сменить и у готового выпуска: отметить другие
(или добавить новый прямо в шаге — он сразу отмечается) и нажать
«Опубликовать».

С вердиктом судьи «не готово» дайджест не публикуется, пока не отмечена
галочка «Опубликовать несмотря на вердикт» — как `--force` у narrator.

«Вид поста в Telegram» в настройках выпуска: видео одним постом или, как
`NEWS_POST=photo`, картинка с подписью и следом аудио. Пакеты для ручной
загрузки — всегда видео.

Каналы, пока нет своего `channels.json`, — пакеты для ручной загрузки и
каналы из `telegram_tems.md` narrator (строки `ИМЯ=id`; `-100…_3` — тема в
группе, уходит как `message_thread_id`). «Добавить канал Telegram» в
шаге «Публикация» или в настройках выпуска (название, id, 16:9 или 9:16) записывает список целиком в
`channels.json` (`AIP_CHANNELS`); дальше каналы берутся оттуда, «убрать» —
удаляет. Токен бота — как у narrator: `$NARRATOR_TELEGRAM_TOKEN`, файл
`$NARRATOR_TELEGRAM_TOKEN_FILE` или `bot_token.md` в каталоге narrator; у
канала можно задать свою переменную `token_env` — только с именем
`AIP_TG_<ИМЯ>`, `AIP_TELEGRAM_TOKEN` или `NARRATOR_TELEGRAM_TOKEN[_<ИМЯ>]`
(чужие секреты окружения вроде `HF_TOKEN` в URL Telegram не уйдут), а её
значение должно выглядеть как токен бота (`123456:ABC…`) — иначе публикация
не отправит ни одного запроса. Тот же список — на вкладке
«Каналы»: там каналы правятся, берутся из движка, там же бот и его подписчики.

## Оформление: плей и плашка «подпишись»

Как у видео narrator: первый кадр ролика — обложка. Постер притемнён, по
центру кнопка «плей», внизу крупная плашка «подпишись». Через 0,8 с
притемнение и плей гаснут, а плашка за секунду плавно уезжает в правый
верхний угол и остаётся там на всех слайдах (внизу слайда — заголовок и
тезисы, поэтому угол верхний). За 2,5 с до конца ролика — и видео, и
шортса — кадр снова притемняется, а плашка за секунду выезжает обратно
крупно вниз по центру, как на обложке, и держится до конца; пункты
последнего слайда успевают показаться до этого. Постер в кадре целиком: квадратная обложка
дайджеста не обрезается, по бокам — её размытая копия. Первый кадр и его
миниатюра (`video-cover.jpg`, `video-thumb.jpg`) уходят в Telegram как
обложка видео — без них Telegram берёт случайный кадр. То же в шортсе.

Галочка «Плашка «подпишись» и кнопка «плей»» в настройках выпуска; у
дайджеста включена по умолчанию, у статьи — выключена. Картинки —
`app/platform/aiplatform/studio/assets/` (копии `library/subscribe.png` и
`library/play.png` narrator), свои — `AIP_STUDIO_STICKER`, `AIP_STUDIO_PLAY`.

## Пометки о запрещённых организациях

Если в тексте выпуска упомянута организация, признанная в РФ
экстремистской, террористической или нежелательной (например, Meta —
«Компания Meta (продукты Facebook и Instagram) признана экстремистской
организацией и запрещена на территории РФ»), то на каждом слайде, где она
звучит, внизу кадра идёт мелкая пометка, а в подпись к посту она
дописывается в конце. Ищем по названиям и продуктам латиницей и кириллицей
с любыми окончаниями («в Инстаграме»). WhatsApp не помечаем: решение суда
на него не распространяется. Галочка «Помечать запрещённые в РФ
организации» в настройках выпуска (включена по умолчанию).

Список по умолчанию — `app/platform/aiplatform/updates/registry.json` (сверен с
перечнями Минюста 16.10.2026): Meta, «Киберпартизаны BY», Silent Crow,
Almaz Capital Partners (экстремистские), Recorded Future, OpenText
(нежелательные). Правки с вкладки «Обновления» ложатся в

## Обновления

- **Модели и пайплайны** — сверка установленного с источниками: mflux
  (PyPI), Flux2CLI (релизы GitHub), ltx-2-mlx (теги GitHub), веса на
  Hugging Face. Версии читаются из путей установки
  (`mflux-0.22.0`, `flux2cli-v3.1.0`, …), у весов — дата установки. Сама
  вкладка ничего не ставит: подсказывает, что поднять в `app/platform/tools/setup-model.sh`.
  Для закрытых репозиториев весов нужен `HF_TOKEN` в окружении.
- **Модели озвучки** — что из моделей движка лежит на диске; «Скачать
  основные» (`make models`), модели mlx для сравнения по выбору и «Перенести
  из ~/.cache» идут фоновыми задачами с логом.
- **Запрещённые организации** — LLM с веб-поиском сверяет список с
  перечнями Минюста и предлагает новую версию; разница показывается
  построчно, применяет её человек. Список можно править и как JSON.

## Общие настройки

Вкладка «Настройки» пишет в `data/settings.json`. Пока там одно: что
выключено. Выключенная модель фото или видео, движок озвучки или отдельный
голос пропадает из выбора во всех вкладках и сценариях, а запрос с ним
получает 400 с подсказкой, где включить. Действует сразу, без перезапуска;
ручная правка файла тоже подхватывается. Движок, у которого выключены все
голоса, считается выключенным. Если выключенный голос был голосом движка по
умолчанию, вместо него берётся первый включённый. Задачи, которые уже
начались, доделываются.
