# Грабли — системные ошибки и предохранители

Здесь не опечатки, а ошибки, которые вычитка не ловит: взяли не тот жанр
артефакта, поставили себе не тот критерий, построили всё на одном выборе.
Внутри своей логики такие результаты выглядят как успех.

**Когда дописывать:** человек отклонил артефакт целиком, а не поправил детали.
**Когда читать:** перед работой в области, где грабли уже были.

> Проверка на соответствие своему заданию не заменяет проверку на пригодность.
> Если результат идеально отвечает брифу, отдельно спроси — тот ли бриф.

## Шаблон записи

```markdown
## N. <Короткое название ошибки>

**Что выпустили.** Факт: какой артефакт, какое решение.
**Реакция.** Дословно, что сказал человек.
**Диагноз.** Какая ошибка системная (не «плохо сделал», а «делал не то»).
**Почему не поймали.** Чем проверяли и почему проверка прошла.
**Предохранитель.** Что изменено (регламент, чек, шаблон), чтобы не повторилось.
```

## 1. Flux2CLI v3.1.0 без mlx.metallib

**Что выпустили.** Фото FLUX.2 через Flux2CLI v3.1.0, поставленный
`setup-model.sh` из релизного zip: в архиве только бинарник.
**Реакция.** FLUX.2 падает на первой генерации: `MLX error: Failed to load
the default metallib` (2026-10-15).
**Диагноз.** Установку считали готовой по факту «бинарник на месте» и
`--help` работает; Metal-шейдеры MLX грузятся только при первом расчёте.
**Почему не поймали.** Тесты платформы идут на фейках; `make smoke` берёт
модель по умолчанию (Z-Image), не FLUX.2.
**Предохранитель.** Строка в «Если не работает при установке»
(`app/platform/README.md`) с командой: `mlx.metallib` из колеса
`mlx-metal==0.31.1` (MLX v0.31.1 у mlx-swift 0.31.6) — рядом с бинарником.
Переустановка Flux2CLI возвращает ошибку. Довести `setup-model.sh`, чтобы
докладывал файл сам, — отдельная задача.

## 2. Python 3.9 из Xcode CLT вместо 3.11+

**Что выпустили.** Сервис на Python 3.11+ (`match`, `X | Y` в типах) и
инструкцию «запусти `python3 -m aiplatform.server`».
**Реакция.** На чистом Mac — `SyntaxError` при импорте: системный
`python3` — 3.9 из Xcode Command Line Tools.
**Диагноз.** Окружение разработчика (Homebrew-питон в `PATH`) приняли за
окружение любого Mac.
**Почему не поймали.** Все запуски шли на одной машине, где `python3` уже
был новым.
**Предохранитель.** Makefile ищет `python3.13`…`python3.11` и
останавливается с подсказкой (DX-001); README и «Быстрый старт» велят
ставить `python@3.12` и запускать через `make`.
