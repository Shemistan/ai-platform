# AI Platform

Один локальный сервис вместо четырёх: генерация фото, видео и озвучки,
библиотека статей, новости и Telegram-каналы плюс сценарии выпуска
«Дайджест новостей», «Видео по статье» и «Пост в канал». Всё работает на
этом Mac (Apple Silicon), модели локальные. Озвучку, статьи, сбор новостей
и Telegram-бота делает движок narrator — он рядом, в
[`app/narrator`](../narrator/README.md); прежний каталог
`07_offline_text-to-word` больше не нужен (перенос данных — ниже).

Шапка — группами: инструменты · сценарии выпуска · материалы · обслуживание.

| Вкладка | Адрес | Что умеет |
|---|---|---|
| Фото | `/photo/` | с нуля по промпту; поправить фото; удалить или заменить объект по маске; расширить кадр; увеличить готовую картинку до 2K/4K (SeedVR2). Шесть моделей (FLUX.2, Qwen-Image, Z-Image, Krea, Ideogram) |
| Видео | `/video/` | по промпту; по ключевым кадрам на таймлайне; «живое фото» — кадр посередине, модель достраивает 4 с до и 4 с после. LTX-2.3 / 2.5, Wan 2.2 |
| Аудио | `/audio/` | текст → mp3: ESpeech, Silero, Supertonic, MLX-клоны; голос, скорость, шаги. Как прочитает модель — на лету; текст из библиотеки или md-файлов (файл с несколькими статьями — в очередь по статье); проверка распознаванием с отчётом по абзацам; образцы голосов-клонов |
| Выпуски | `/board/` | все выпуски всех сценариев: ждут тебя, идут, опубликованы, черновики; публикация в один клик; архив; «Что работает» — просмотры и прирост подписчиков по сценарию, длине и формату. В шапке — счётчик ждущих |
| Дайджест новостей | `/studio/?scenario=digest` | движок собирает новости дня, агент пишет пересказ, судья проверяет → видео и публикация; вердикт судьи «не готово» держит публикацию |
| Видео по статье | `/studio/?scenario=article` | готовая статья → видео и публикация; сцены-главы, код, итог и полоса главы |
| Пост в канал | `/studio/?scenario=post` | свой постер, свой mp3 (или озвучка подписи) и подпись → видео «постер под звук» или картинка с аудио → в каналы |
| Статьи | `/library/` | библиотека статей для прослушивания: по ссылке или своим текстом; текст для озвучки (как есть или агентом), озвучка, проверка, отправка в канал, «Сделать видео»; озвучить все новые, разослать неотправленное |
| Новости | `/news/` | источники с журналом сбора и пользой, «Собрать»; главное за день; добор упавших источников агентом; обзоры недели и месяца для YouTube (суфлёр, материалы, пост) |
| Каналы | `/channels/` | каналы публикации всех сценариев; бот движка; подписчики бота и приём подписок |
| Обновления | `/updates/` | новые версии пайплайнов и весов фото и видео; модели озвучки — что на диске, скачать, перенести; список запрещённых в РФ организаций для пометок в видео |
| Настройки | `/settings/` | общие настройки платформы: какие модели фото и видео, движки озвучки и голоса включены; дайджест по расписанию и уведомления; обновление отклика; уборка старых данных |

Тяжёлые модели идут по одной: у вкладок общий GPU-замок. Пока одна модель
работает, задача другой вкладки ждёт со статусом «Ждёт GPU (занят: …)», а
шапка показывает, кто занял GPU.

## Запуск

```sh
cd app/platform
make demo   # без моделей и сети: фейковые генераторы, TTS, LLM и новости
make run    # на настоящих моделях
```

Открыть: http://127.0.0.1:8780. Нужны Python 3.11+ и ffmpeg (`brew install ffmpeg`).
Системный `python3` на Mac — 3.9 из Xcode CLT: Makefile сам возьмёт `python3.13`,
`python3.12` или `python3.11` из PATH, а если их нет — остановится с подсказкой
(`brew install python@3.12` или `uv python install 3.12`, затем `make PYTHON=python3.12 …`).
Python-зависимостей у сервиса нет; у движка `app/narrator` они свои (uv), первый
`make check` в нём их ставит.

Живость: `curl -s 127.0.0.1:8780/api/health` → `{"ok": true, "version", "uptime_s",
"schedule"}`. Без внешних вызовов (ffmpeg и narrator не трогает); `schedule` —
настройки дайджеста и итог последнего запуска по расписанию.

Готовность: `curl -s 127.0.0.1:8780/api/ready` → 200 и список проверок, если
сервис может выпустить дайджест, иначе 503 и имена непрошедших в `failed`:
`problems` (баннер «Проблемы» пуст), `disk` (на диске данных от
`AIP_MIN_FREE_GB`, 5 ГБ), `models_dir` (каталог моделей примонтирован),
`schedule` (поток расписания тикал не позже 2×`AIP_SCHEDULE_TICK_S`), `token`
(у каналов дайджеста есть токен бота), `last_digest` (сегодняшний дайджест не
упал). `/api/status` показывает, сколько держится GPU-замок (`gpu_held_s`).

**Лог процесса** — `data/logs/platform.log`, JSON-строка на событие
(`{ts, level, event, project, step, task, duration_s, error}`), ротация
10 МБ × 5: старт и стоп, тики расписания, задачи и шаги выпусков с
длительностью, публикации (канал, `message_id`), уборка, таймауты,
уведомления, необработанные ошибки HTTP и запросы, кроме чтения (опросы
`/api/status` не пишутся). «Почему вчера не вышел дайджест»:
`grep -E 'schedule|step.failed|publication' data/logs/platform.log`.

**Остановка.** SIGTERM (launchd, `kill`, перезагрузка): новые POST получают
503, процессы моделей гасятся всей группой, сервис выходит за ≤15 с. Пока
процесс модели жив, его pid лежит в `data/run/`; процессы, пережившие
аварийный конец платформы, гасятся при следующем старте. Шаг выпуска,
прерванный остановкой, после рестарта даёт уведомление «Выпуск прерван
перезапуском», а выпуск, который шёл сам (расписание, «Запустить всё»), один
раз продолжает этот шаг; публикация сама не повторяется.

**Лимиты времени.** Зависший процесс снимается по таймауту и отпускает
GPU-замок: LLM — 10 мин, картинка — 15, сборка видео — 30, видео — 60,
озвучка — 90, сбор новостей — 30. Свои значения (минуты, `total` — весь
запуск, `idle` — без вывода) — в `data/settings.json`:
`"timeouts": {"video": {"total": 120, "idle": 20}}`.

### Автозапуск

Расписание дайджеста живёт внутри процесса: нет процесса — нет выпуска. Чтобы
сервис поднимался сам при входе в систему и после падения, поставь
LaunchAgent. Один раз, в обычном терминале **из основного checkout** (агент
запомнит этот каталог):

```sh
cd app/platform
make install-agent    # ~/Library/LaunchAgents/com.aiplatform.server.plist + чекер дайджеста
make agent-status     # состояние агентов и ответ /api/health
make uninstall-agent  # убрать оба агента; процесс больше не перезапускается
```

- Сервис запускается как `make run` (берёт `local.mk`), `PATH` с brew, uv и
  claude подставляется при установке: launchd не читает `.zshrc`. Поставил
  новую команду в другой каталог — `make install-agent` ещё раз.
- Упал или убит (`kill -9`) — launchd поднимет его через ≤30 с
  (`ThrottleInterval`). Штатный выход с кодом 0 не перезапускается.
- Перезапуск после обновления кода: `launchctl kickstart -k gui/$(id -u)/com.aiplatform.server`.
- Логи: `data/logs/platform.log` (см. выше; под launchd он же — в
  `~/Library/Logs/aiplatform/server.err.log`), вывод старта —
  `server.log`, чекер — `digest-check.log`.
- Mac спит в 07:00 — расписание не сработает. Будить его к выпуску:
  `sudo pmset repeat wakeorpoweron MTWRFSU 06:55:00` (снять — `sudo pmset repeat cancel`).

**Внешний чекер дайджеста.** Алерты платформы шлёт её же процесс; если он
мёртв, сказать некому. Второй агент `com.aiplatform.digest-check` раз в день
(время дайджеста из настроек + 30 мин, по умолчанию 09:00; своё —
`AIP_CHECK_AT=ЧЧ:ММ make install-agent`) запускает `tools/digest_check.py`:
сервис не ответил — «Сервис недоступен», расписание включено, а дайджеста за
день нет — «Дайджест не создан», выпуск упал — «Дайджест упал». Сообщение
уходит ботом прямо в Telegram, мимо платформы. Токен бота и твой chat id —
в Keychain, не в файлах:

```sh
security add-generic-password -U -s aiplatform-digest-check -a telegram-token -w '<токен бота>'
security add-generic-password -U -s aiplatform-digest-check -a telegram-chat -w '<chat id>'
make digest-check     # проверить вручную (или AIP_ALERT_TG_TOKEN / AIP_ALERT_TG_CHAT в env)
```

Поменял время дайджеста — `make install-agent` заново, чтобы сдвинулся чекер.
По желанию — heartbeat-сервис (healthchecks.io): `AIP_HEARTBEAT_URL=<url>` в
`local.mk`, платформа пингует его после каждого тика расписания, и сервис сам
напишет, если пинги пропали.

### Данные и бэкап

Данные живут вне рабочей копии — в `~/Library/Application Support/aiplatform`
(`AIP_DATA_DIR`): чистка рабочей копии, ветки и worktree агента их не
трогают. Пока этого каталога нет, а старый `app/platform/data` есть,
платформа работает со старым. Перенос — один раз, в обычном терминале:

```sh
make migrate-data          # копия data/ (и channels.json) в новый каталог; старое не удаляется
launchctl kickstart -k gui/$(id -u)/com.aiplatform.server
```

Проверь доску и каналы — после этого `app/platform/data` можно удалить.
Библиотека narrator (статьи, база новостей, подписчики бота) лежит в
`<AIP_NARRATOR_DIR>/library` (сейчас — `~/my_track/07_offline_text-to-word/library`)
или в `$NARRATOR_LIBRARY`.

**Бэкап** — маленькие невосстановимые файлы: настройки, каналы,
расписание, `project.json` / `published.json` / тексты выпусков, журнал
запусков, `local.mk`, библиотека narrator без mp3/wav/mp4 и состояние бота
(`telegram.json`). Без медиа, весов, задач вкладок и кэша; токен бота не
кладётся. Архив шифруется [`age`](https://age-encryption.org) и кладётся в
`AIP_BACKUP_DIR`; архивы старше 30 дней удаляются. Один раз:

```sh
brew install age
mkdir -p ~/.config/aiplatform && age-keygen -o ~/.config/aiplatform/backup-key.txt
# копию ключа — в менеджер паролей: без него архив не открыть
# в local.mk:
#   AIP_BACKUP_DIR=$(HOME)/Library/Mobile Documents/com~apple~CloudDocs/aiplatform-backups
#   AIP_BACKUP_AGE_RECIPIENT=age1…   (строка «public key» из age-keygen)
make backup                # первый архив; потом — каждый день агентом
make install-agent         # ставит и com.aiplatform.backup (03:30, AIP_BACKUP_AT)
make restore FILE=<архив> TO=~/aiplatform-restore   # только в пустой каталог
```

Возраст последнего бэкапа — в `/api/ready` (проверка `backup`; не настроен —
не мешает, старше 48 ч — 503). Восстановление на живой сервис — в
[runbook](../../docs/runbook.md), сценарий 5.

Тяжёлое и восстановимое — веса моделей, кэш генераций, `.venv` движка, кэш
Hugging Face — исключить из Time Machine: `make tm-exclude` (`tmutil
addexclusion` по каждому пути).

### Обновление и откат

Живой сервис работает не из рабочей копии (там агент делает ветки), а из
отдельного checkout на теге релиза: `~/apps/aiplatform` (`AIP_LIVE_DIR`).
Один раз:

```sh
git clone <url репозитория> ~/apps/aiplatform
cp app/platform/local.mk ~/apps/aiplatform/app/platform/     # local.mk не в git
make -C ~/apps/aiplatform/app/platform uninstall-agent install-agent   # агент запомнит живой каталог
```

После слияния PR в `main` — человек, из любого checkout `app/platform`:

```sh
make release-tag           # тег vYYYY.MM.DD (второй за день — .2) на origin/main и push
make deploy TAG=v2026.10.17   # бэкап → git fetch → checkout тега в живом checkout → перезапуск агента
make deployed              # какой тег сейчас у живого сервиса
```

**Откат** — тот же `make deploy TAG=<прошлый тег>` (его печатает каждый
деплой, история — `~/Library/Logs/aiplatform/deploy.log`). Выпуски
(`project.json`) мигрируют только вперёд: выпуск, созданный или открытый
новой версией, старый код может прочитать не так. После отката такие
выпуски не перезапускай; нужно вернуть данные как были — восстанови бэкап,
который `make deploy` сделал перед обновлением (runbook, сценарий 5).

### Переезд со старого narrator

Один раз, в обычном терминале из основного checkout:

```sh
sh app/narrator/tools/import-old.sh ~/my_track/07_offline_text-to-word
```

Скрипт копирует `library/` (статьи, база новостей, подписчики бота),
`telegram_tems.md` и `bot_token.md` и ничего не удаляет. Проверь «Статьи»,
«Новости» и «Каналы» — после этого старый каталог можно удалить.

### Если не работает при установке

Грабли установки и разработки. Чего не хватает работающему сервису, он
пишет сам — баннер «Проблемы» вверху страниц и строки `⚠` при `make run`.

| Симптом | Причина | Что сделать |
|---|---|---|
| `SyntaxError` на `match` при `python3 -m aiplatform.server`, или `make run` останавливается с подсказкой про Python | системный `python3` на Mac — 3.9 из Xcode CLT, сервису нужен 3.11+ | `brew install python@3.12` (или `uv python install 3.12`), затем `make PYTHON=python3.12 run`; запускать через `make`, а не голым `python3` |
| Баннер «Аудио: у движка по умолчанию … нет весов» или озвучка падает с «нет модели …» | `make models` в `app/narrator` не запускали, или веса лежат на неподключённом диске | `cd app/narrator && make models`; для MLX-движков — `make models-mlx E=higgs`; другой каталог — `NARRATOR_MODELS_DIR=~/local_models` |
| Модели фото или видео нет в списке или задача падает без весов | `make models M=…` не запускали, `AIP_MODELS_DIR` указывает на неподключённый `/Volumes/External SSD` | подключить диск или `make models M=<id> AIP_MODELS_DIR=~/local_models`; что стоит — вкладка «Обновления» |
| FLUX.2 падает: `MLX error: Failed to load the default metallib` | релиз Flux2CLI v3.1.0 идёт без `mlx.metallib`, а `setup-model.sh` его не докладывает | положить рядом с бинарником `mlx.metallib` из колеса `mlx-metal==0.31.1` (версия MLX у mlx-swift 0.31.6): `D=$(mktemp -d) && uv pip install --target "$D" mlx-metal==0.31.1 && cp "$D"/mlx/lib/mlx.metallib ~/.local/share/photogen/flux2cli-v3.1.0/`. Переустановка Flux2CLI возвращает ошибку — повторить |
| Первая генерация FLUX.2 Klein долго «висит» на старте, на системном диске растёт `~/.cache/huggingface` | текстовый энкодер Klein (`Qwen3-8B-MLX-8bit`, ~8 ГБ) `setup-model.sh` не ставит — Flux2CLI качает его при первом запуске | подождать первый запуск (нужна сеть); руками Flux2CLI запускать с `HF_HOME="$AIP_MODELS_DIR/.photogen-cache/hf"`, иначе копия ляжет в `~/.cache` |
| Дайджест или промпты слайдов падают: `claude: command not found` | claude CLI (Claude Code) не установлен или его нет в `PATH` процесса — у launchd `PATH` короче, чем в терминале | установить Claude Code, залогиниться, проверить `claude --version`; под launchd — полный путь в `AIP_LLM_CMD` и `CLAUDE=/полный/путь/claude` для `make news` движка |
| Агент (Claude Code) не может скачать модели, `make check` движка падает на `uv`, нет GPU | sandbox агента: сети к Hugging Face и PyPI нет, GPU нет, `~/.cache/uv` закрыт на запись | модели и первую установку зависимостей — в обычном терминале (`make models`, `make check` в `app/narrator`); `./narrate` сам переносит кэш uv в `$TMPDIR`, для своих команд — `UV_CACHE_DIR=$TMPDIR/uv-cache` |
| Шаг «Постер» дайджеста ждёт картинку, локальная модель обложку не рисует | так задумано: обложку дайджеста делают в ChatGPT по `image_prompt.md` выпуска — кириллические заголовки локальные модели рисуют хуже | сгенерировать в ChatGPT по промпту шага 2 и перетащить в шаг или положить `cover.*` в каталог выпуска narrator; локально — галочка «локальная модель» |
| `git commit` не гоняет `./check`, сообщение коммита не проверяется | хуки репозитория не включены на этой машине | `sh bootstrap.sh` в корне репозитория |

Эксплуатация живого сервиса — дайджест не вышел, GPU завис, диск не
примонтирован, Telegram не принимает — не здесь: это runbook (задача
REL-015). Системные ошибки агентов и предохранители — `docs/грабли.md`.

## Сценарии: как устроен выпуск

Выпуск — цепочка шагов. Каждый шаг виден на странице, его результат можно
поправить руками, заменить своим файлом или перезапустить. «Запустить всё»
выполняет каждый шаг, для которого всё готово. Шаг, который ждёт твоих
файлов (постер, картинки, видео, озвучка), держит только то, что без них
не собрать: остальное идёт дальше. Файлы можно класть, пока выпуск работает;
как только загружен последний недостающий, сборка продолжается сама. После
«Остановить» выпуск сам не продолжается — до следующего «Запустить всё».

| # | Шаг | Что делает | Можно вручную |
|---|---|---|---|
| 1 | Текст | дайджест: движок собирает новости, агент пишет пересказ, судья проверяет выпуск — его вердикт и отчёт видны в шаге; статья: вставленный текст; пост: подпись (и текст для озвучки) | править текст; галочка «пауза после текста» |
| 2 | Промпт постера | дайджест: промпт обложки из выпуска narrator (`image_prompt.md`: гофер в сцене по событиям дня и заголовки на картинке), нет его — LLM пишет такой же; статья: LLM пишет промпт обложки | править, скопировать |
| 3 | Постер | дайджест: по умолчанию «загружу свой» — обложку делают в ChatGPT по промпту и перетаскивают сюда или кладут `cover.*` в каталог выпуска narrator (подхватится сама, после правки — «Перезапустить шаг»); иначе галочка «локальная модель» → задача во вкладке «Фото» (у дайджеста квадрат 1024×1024); иначе промпт и окно, куда перетащить картинку, сделанную во внешней модели | загрузить свою |
| 4 | Слайды | LLM делит текст на слайды без ограничения числа — примерно по слайду на «время слайда» озвучки (настройка, ~4–12 с; по умолчанию 6 с, у дайджеста 8 с) и с текстом, который за это время читается, начало — абзац и фраза. Слайды двух сортов вперемешку: картинка (заголовок, тезисы, промпты картинки и видео) и динамические сцены, которые рисует сборка: пункты, крупное число, график столбцами или линией, схема из шагов, сравнение «было / стало», цитата, глава, код (строки набираются), итог с галочками; плюс название и подпись к посту. Есть главы — сверху видео полоса прогресса с названием текущей главы | править JSON |
| 5 | Картинки | только для слайдов-картинок: «локальная модель» → задачи во вкладке «Фото»; «сделаю сам» → у каждого такого слайда промпт и окно справа, куда перетащить готовую картинку из внешней модели. На видео картинка — фон, длинный слайд режется на планы до 5 с с разным движением камеры (наезд, панорама, отъезд). Настройка «увеличить» — каждую сгенерированную картинку и постер до 2K или 4K (SeedVR2); смена только увеличения не перерисовывает картинки. Можно выключить — будет градиент | перетащить свою картинку любому слайду |
| 6 | Ролики | галочка «добавить ролики»: LLM выбирает до 3 самых динамичных слайдов и пишет им промпт видео — там вместо картинки ролик 5 с (крутится по кругу без своего звука). «Локальная модель» → задачи во вкладке «Видео» (LTX / Wan, 704×448); «сделаю сам» → промпт и окно для готового ролика (MP4, MOV, WebM), «Продолжить без недостающих» — собрать с тем, что есть | перетащить свой ролик |
| 7 | Озвучка | задача во вкладке «Аудио» или свой mp3 (например, из Gemini TTS) | загрузить свой |
| 8 | Видео | ffmpeg (кадр 16:9 или как постер — см. ниже): постер 2 с (с оформлением — 3 с, см. ниже), затем слайды под фразы озвучки; слайд не сменится, пока не прочитан (см. ниже). Ритм: каждые 3–5 с в кадре что-то меняется — новый слайд, следующий элемент сцены (пункт, столбец, шаг схемы, слова цитаты) или новый план картинки; когда всё показано, а слайд идёт, подсветка переходит по элементам каждые 4 с | — |
| 9 | Шортс 9:16 | галочка «шортс»: LLM пишет сценарий на 45–60 с, озвучка, вертикальный рендер 1080×1920 | править сценарий |
| 10 | Публикация | в выбранные каналы, после кнопки «Опубликовать» (или сразу — галочка); в Telegram с оформлением — обложка видео и миниатюра | править подпись |

У сценария «Пост в канал» шагов слайдов, картинок, роликов и шортса нет:
постер и mp3 — свои (или озвучка подписи локальной моделью), видео — постер
на всю длину звука с оформлением канала, подпись — со счётчиком 1024 знаков.

«Скорость в видео» (×0,75–×2; у дайджеста по умолчанию ×1,25, как публиковали
в narrator) ускоряет озвучку видео и шортса через `atempo` — голос не
меняет высоту, слайды подстраиваются под новую длину, а обложка и переезд
плашки идут в обычном темпе. Смена скорости пересобирает видео, озвучку — нет.

«Слайды»: «время слайда» (~4, 6, 8, 10, 12 с) — ориентир для плана, сколько
держится слайд и сколько на нём текста; смена перестраивает план. «Время на
чтение» — слайд держится не меньше, чем читается его текст: 1 с + слова на
экране (заголовок, тезисы, пункты, подписи) по 3 слова в секунду («обычно»)
или по 2 («медленно»), не больше 15 с. Следующие слайды сдвигаются и
догоняют свою фразу на длинных слайдах; отставание от озвучки от 2 с видно в
логе сборки. «Не ждать» — слайд меняется вместе с фразой, как раньше. Смена
пересобирает видео и шортс, план — нет.

«Кадр видео» в оформлении: «как постер» (ширина 1080, пропорции картинки
обложки — квадратная обложка дайджеста даёт 1080×1080, как у narrator; не
уже 9:16 и не шире 16:9), «квадрат 1:1» или «широкий 16:9». У дайджеста по
умолчанию «как постер», у статьи — 16:9. Под кадр не 16:9 картинки слайдов
рисуются квадратными (1024×1024). Шортс всегда 9:16. Смена кадра
пересобирает только видео: готовые картинки слайдов остаются (кадр берёт их
с обрезкой), новые рисуются уже под него.

Правка результата шага сбрасывает только зависящие от него шаги: новая
картинка постера пересоберёт видео, но не тронет озвучку и слайды.

У каждого шага, в том числе в готовом выпуске, — «Параметры шага» прямо в
его карточке: у постера — режим, модель и увеличение, у картинок и роликов —
режим и модель, у озвучки — движок и голос, у сборки видео и шортса — кадр,
скорость, оформление и пометки. Поменял → «Перезапустить шаг»: шаг
пересобирается уже с новыми параметрами (`POST …/run {step, settings}`), они
же сохраняются в настройках выпуска. Шаги после него сбрасываются — их
соберёт «Запустить всё» или их собственный «Перезапустить шаг».

## Выпуски: доска, повтор, оценка, черновик

**Доска «Выпуски».** Все выпуски по группам. У ждущего — шаг и что
нужно; если ждёт только публикация и каналы выбраны — кнопка
«Опубликовать» прямо на карточке. «В архив» убирает выпуск с доски и из
списков сценария (файлы остаются, «Архив» на доске их показывает).

**Не начинать заново.** Новый выпуск по тому же дню (дайджест) или тому же
тексту (статья, пост) не создаётся молча: страница предлагает открыть
существующий или всё же создать новый. «Копия выпуска» переносит
настройки и всё готовое до сборки — попробовать другой вариант, не трогая
этот. Картинки, ролики и озвучка с теми же входами (промпт, модель,
размер, увеличение; текст, движок, голос, скорость) второй раз не
генерируются — берутся из кэша `data/studio/cache/` (клон APFS, место не
удваивается), в журнале — «из кэша». «Перезапустить шаг» кэш не читает:
им просят новый вариант.

**До запуска.** У выпуска и в форме нового выпуска — оценка времени
(картинки, ролики, озвучка, сборка — по медиане задач этой машины; без
истории — по умолчанию) и предупреждения: канал 9:16 без шортса, канал без
токена, неустановленная модель, ожидание твоих файлов, текст длиннее ~12
минут. Публикация сначала проверяет все выбранные каналы и только потом
отправляет: при ошибке не уходит никуда.

**Черновик.** Галочка «Черновик» в настройках выпуска: без картинок и
роликов, кадр вполовину — быстро посмотреть структуру и ритм. «Сделать
чистовик» снимает её и дособирает выпуск; озвучка и слайды не
переделываются. Для длинной статьи — «Разбить на серию» (по заголовкам `#`
и абзацам, части по ~1000 слов, исходный выпуск — в архив) и «Сделать
выжимку» (LLM пишет текст на 5–8 минут — новый выпуск).

**Расписание и уведомления** («Настройки»). Дайджест сам в заданное время —
за вчера или за сегодня; если платформа была выключена, он соберётся при
запуске в тот же день. Уже собранный или убранный в архив день не
пересоздаётся. Уведомления: выпуск ждёт тебя, упал или опубликован — в
Telegram, если в «Настройках» указан твой чат (id или @username; пишет бот
каналов, токен — как у каналов; сначала напиши боту `/start`), и на Mac
системные (osascript), своя команда — `AIP_NOTIFY_CMD` (заголовок — первая
строка stdin). Указал чат — уведомления включаются сами. «Проверить
уведомление» шлёт тестовое и показывает ошибку, если не дошло; итог каждой
доставки — в логе процесса. Журнал — `data/notifications.log` (с ротацией).

**Отклик.** При публикации в Telegram запоминаются id сообщения и число
подписчиков. «Обновить отклик» на доске (и раз в сутки сам) берёт
подписчиков через Bot API (`getChatMemberCount`, бот — админ канала), а
просмотры — со страницы `t.me/<канал>/<id>?embed=1`: только у публичных
каналов. У пакетов для YouTube и TikTok и у приватных каналов просмотры
вносятся руками в карточке на доске.

**Уборка** («Настройки»). Сколько места у задач вкладок, выпусков, архива,
кэша и загрузок. «Убрать сейчас» (и раз в сутки сам — включено по
умолчанию) удаляет старше 7–90 дней только восстановимое: завершённые
задачи «Фото», «Видео», «Аудио» (выпуски хранят свои копии файлов), давние
записи кэша, загрузки и выпуски из архива. Опубликованный выпуск через
`trim_days` (14) после публикации теряет картинки слайдов, исходники клипов
и файлы шортса (остаются `video.mp4`, `short.mp4`, `project.json`,
`published.json`, тексты и постер), а через `archive_days` (60) сам уходит
в архив — такой выпуск уборка архива не удаляет. Неопубликованные выпуски
и идущие задачи не трогаются. Значения — в `data/settings.json`, раздел
`cleanup` (0 — выключено).

**Место на диске.** Перед GPU-задачей (фото, видео, озвучка) и сборкой
видео платформа проверяет свободное место на диске данных: меньше
`cleanup.min_free_gb` (по умолчанию 10 ГБ; в `make demo` проверки нет) —
задача не стартует с ошибкой «свободно X ГБ…, нужно от Y ГБ», а владельцу
уходит уведомление «Мало места на диске» (не чаще раза в час).

## Публикация в Telegram

Вместо `make news-publish` в narrator — кнопка «Опубликовать» в шаге
«Публикация»: рядом выбор каналов и галочка «Опубликовать повторно». Видео
уходит одним постом с подписью к посту (и обложкой, если есть оформление).
В канал, куда выпуск уже ушёл, повторно отправляется только с галочкой —
как `FORCE=1`. У дайджеста по умолчанию выбран канал новостей narrator
(`VOICE_NEWS`). Каналы можно сменить и у готового выпуска: отметить другие
(или добавить новый прямо в шаге — он сразу отмечается) и нажать
«Опубликовать».

С вердиктом судьи «не готово» дайджест не публикуется, пока не отмечена
галочка «Опубликовать несмотря на вердикт» — как `--force` у narrator.

«Вид поста в Telegram» в настройках выпуска: видео одним постом или, как
`NEWS_POST=photo`, картинка с подписью и следом аудио. Пакеты для ручной
загрузки — всегда видео.

Каналы, пока нет своего `channels.json`, — пакеты для ручной загрузки и
каналы из `telegram_tems.md` narrator (строки `ИМЯ=id`; `-100…_3` — тема в
группе, уходит как `message_thread_id`). «Добавить канал Telegram» в
шаге «Публикация» или в настройках выпуска (название, id, 16:9 или 9:16) записывает список целиком в
`channels.json` (`AIP_CHANNELS`); дальше каналы берутся оттуда, «убрать» —
удаляет. Токен бота — как у narrator: `$NARRATOR_TELEGRAM_TOKEN`, файл
`$NARRATOR_TELEGRAM_TOKEN_FILE` или `bot_token.md` в каталоге narrator; у
канала можно задать свою переменную `token_env`. Тот же список — на вкладке
«Каналы»: там каналы правятся, берутся из движка, там же бот и его подписчики.

## Оформление: плей и плашка «подпишись»

Как у видео narrator: первый кадр ролика — обложка. Постер притемнён, по
центру кнопка «плей», внизу крупная плашка «подпишись». Через 0,8 с
притемнение и плей гаснут, а плашка за секунду плавно уезжает в правый
верхний угол и остаётся там на всех слайдах (внизу слайда — заголовок и
тезисы, поэтому угол верхний). За 2,5 с до конца ролика — и видео, и
шортса — кадр снова притемняется, а плашка за секунду выезжает обратно
крупно вниз по центру, как на обложке, и держится до конца; пункты
последнего слайда успевают показаться до этого. Постер в кадре целиком: квадратная обложка
дайджеста не обрезается, по бокам — её размытая копия. Первый кадр и его
миниатюра (`video-cover.jpg`, `video-thumb.jpg`) уходят в Telegram как
обложка видео — без них Telegram берёт случайный кадр. То же в шортсе.

Галочка «Плашка «подпишись» и кнопка «плей»» в настройках выпуска; у
дайджеста включена по умолчанию, у статьи — выключена. Картинки —
`aiplatform/studio/assets/` (копии `library/subscribe.png` и
`library/play.png` narrator), свои — `AIP_STUDIO_STICKER`, `AIP_STUDIO_PLAY`.

## Пометки о запрещённых организациях

Если в тексте выпуска упомянута организация, признанная в РФ
экстремистской, террористической или нежелательной (например, Meta —
«Компания Meta (продукты Facebook и Instagram) признана экстремистской
организацией и запрещена на территории РФ»), то на каждом слайде, где она
звучит, внизу кадра идёт мелкая пометка, а в подпись к посту она
дописывается в конце. Ищем по названиям и продуктам латиницей и кириллицей
с любыми окончаниями («в Инстаграме»). WhatsApp не помечаем: решение суда
на него не распространяется. Галочка «Помечать запрещённые в РФ
организации» в настройках выпуска (включена по умолчанию).

Список по умолчанию — `aiplatform/updates/registry.json` (сверен с
перечнями Минюста 16.10.2026): Meta, «Киберпартизаны BY», Silent Crow,
Almaz Capital Partners (экстремистские), Recorded Future, OpenText
(нежелательные). Правки с вкладки «Обновления» ложатся в
`data/registry.json` и действуют со следующей сборки видео.

## Обновления

- **Модели и пайплайны** — сверка установленного с источниками: mflux
  (PyPI), Flux2CLI (релизы GitHub), ltx-2-mlx (теги GitHub), веса на
  Hugging Face. Версии читаются из путей установки
  (`mflux-0.22.0`, `flux2cli-v3.1.0`, …), у весов — дата установки. Сама
  вкладка ничего не ставит: подсказывает, что поднять в `tools/setup-model.sh`.
  Для закрытых репозиториев весов нужен `HF_TOKEN` в окружении.
- **Модели озвучки** — что из моделей движка лежит на диске; «Скачать
  основные» (`make models`), модели mlx для сравнения по выбору и «Перенести
  из ~/.cache» идут фоновыми задачами с логом.
- **Запрещённые организации** — LLM с веб-поиском сверяет список с
  перечнями Минюста и предлагает новую версию; разница показывается
  построчно, применяет её человек. Список можно править и как JSON.

## Общие настройки

Вкладка «Настройки» пишет в `data/settings.json`. Пока там одно: что
выключено. Выключенная модель фото или видео, движок озвучки или отдельный
голос пропадает из выбора во всех вкладках и сценариях, а запрос с ним
получает 400 с подсказкой, где включить. Действует сразу, без перезапуска;
ручная правка файла тоже подхватывается. Движок, у которого выключены все
голоса, считается выключенным. Если выключенный голос был голосом движка по
умолчанию, вместо него берётся первый включённый. Задачи, которые уже
начались, доделываются.

## Настройка

Переменные окружения — в `local.mk` рядом с Makefile (не в git) или в
окружении. Пустое значение — значение по умолчанию. Готовый пример с путями,
которые ставит `make models`: `cp local.mk.example local.mk`.

| Переменная | По умолчанию | Что это |
|---|---|---|
| `AIP_PORT`, `AIP_HOST` | `8780`, `127.0.0.1` | где слушать |
| `AIP_DATA_DIR` | `~/Library/Application Support/aiplatform`; пока его нет, а `app/platform/data` есть — старый путь | задачи, загрузки, выпуски, настройки, каналы (вне рабочей копии — см. «Данные и бэкап») |
| `AIP_MODELS_DIR` | `/Volumes/External SSD/local_models` | веса фото- и видеомоделей |

### Установка моделей

Фото и видео ставит `tools/setup-model.sh` из этого репозитория — соседние
репозитории photogen и videogen не нужны. Нужны Mac на Apple Silicon, сеть,
`uv` и ffmpeg (`brew install uv ffmpeg`), Python 3.11+ (см. «Запуск»). Из
`app/platform`:

```sh
make models M=--list                       # какие модели есть
make models M="z-image-turbo ltx-2.3-q4"   # минимум: одна модель фото и одна видео, без лицензий и токенов
make run
```

Скрипт ставит пайплайны в `~/.local/share/photogen` и `~/.local/share/videogen`
(`PHOTOGEN_HOME`, `VIDEOGEN_HOME`), качает веса в `AIP_MODELS_DIR` (по умолчанию
`/Volumes/External SSD/local_models`) и дописывает в `local.mk` строки
`AIP_MODELS_DIR`, `AIP_PHOTO_*`, `AIP_VIDEO_*` — остальное в `local.mk` не
трогает. Повторный запуск докачивает недостающее, установленное пропускает.
Нет внешнего диска — другой каталог:
`make models M=z-image-turbo AIP_MODELS_DIR=~/local_models`.

Закрытые лицензией веса (FLUX.2, Ideogram 4, LTX-2.5): открыть страницу
модели на Hugging Face, принять условия, создать токен типа Read и запустить
`HF_TOKEN=hf_… make models M=<id>`; скрипт подскажет ссылку.

| Модель | Вкладка | Веса на диске | Примечание |
|---|---|---|---|
| `z-image-turbo` | фото | ~10 ГБ | по умолчанию для постеров и слайдов, без токена |
| `krea-2` | фото | ~15 ГБ | без токена |
| `qwen-image-2512` | фото | ~26 ГБ | без токена |
| `ideogram-4` | фото | не замерено (q4 mflux — обычно 10–25 ГБ) | нужен `HF_TOKEN` |
| `flux2-klein-9b` | фото | ~18 ГБ + текстовый энкодер при первой генерации | Flux2CLI, нужен `HF_TOKEN` |
| `flux2-dev` | фото | ~65 ГБ — оценка, не замерено (Flux2CLI хранит bf16-веса 32B) | Flux2CLI, нужен `HF_TOKEN` |
| `ltx-2.3-q4` | видео | ~19 ГБ + 7,5 ГБ энкодер Gemma 3 12B | без токена; живое фото |
| `ltx-2.5-q4` | видео | ~27 ГБ (энкодер внутри) | модель видео по умолчанию, нужен `HF_TOKEN` |
| `wan-2.2-t2v-q4` | видео | ~27 ГБ | только по промпту, без звука |

Размеры — `du` установленных каталогов (файлы режима `--distilled` у LTX;
`FULL=1` качает репозиторий целиком — в разы больше). Сверху — пайплайны:
окружение mflux ~1,1 ГБ, Flux2CLI ~0,2 ГБ, ltx-2-mlx ~0,4 ГБ, запускатель
Wan ~0,5 ГБ. Апскейлер SeedVR2 3B ставить не нужно — он идёт в окружении
mflux, веса (~7 ГБ) докачиваются в `AIP_MODELS_DIR/.photogen-cache` при
первом увеличении.

Озвучка и новости: в `app/narrator` — `make models`; для дайджеста нужен ещё
claude CLI. Данные старого narrator (статьи, база новостей, каналы, токен
бота) переносит один раз
`sh app/narrator/tools/import-old.sh ~/my_track/07_offline_text-to-word`.

### Каналы публикации

Скопируй `channels.example.json` в `channels.json` и поправь. Типы:

- `telegram` — видео отправляется ботом (`sendVideo`, до 50 МБ) с подписью из
  шага «Публикация». Токен бота — в переменной из `token_env` (например,
  `export AIP_TELEGRAM_TOKEN=…`); в файлы и логи он не пишется.
- `manual` — пакет для ручной загрузки: `video.mp4`, `title.txt`,
  `description.txt` в `data/studio/projects/<id>/publish/<канал>/`. Так
  сделано для YouTube, TikTok и Instagram: их API требуют OAuth-приложений.

`format`: `landscape` — уходит видео 16:9, `vertical` — шортс 9:16.
Без `channels.json` доступны два пакета для ручной загрузки.

## Проверка

```sh
make check   # ruff (если стоит), node --check, unittest — всё на фейках
make smoke   # на настоящих моделях: картинка, фраза озвучки, черновик статьи — с временем шагов
```

Тесты гоняют все вкладки и все сценарии целиком через HTTP с фейковыми
моделями, фейковым движком (`aiplatform/fakes/fake_narrate.py` — те же
команды и JSON моста) и настоящим ffmpeg. Тесты движка — `make check` в
`app/narrator`; корневой `./check` гоняет оба.

`make smoke` поднимает платформу в своём процессе на временном каталоге
данных (настоящие `data/` не трогаются) и проходит три шага через HTTP API;
код выхода 0 — всё прошло. `python -m aiplatform.smoke --fake` — то же на
фейках.

## Что проверено на настоящих моделях

По выпускам в `data/` за 15–16.10.2026 платформа работала на этой машине:
картинки Z-Image Turbo и увеличение SeedVR2 до 4K, ролики LTX, озвучка
Higgs (статья на 38 минут), сбор дайджеста движком narrator с агентом и
судьёй, публикация в Telegram и пакеты для ручной загрузки.

Новое из «Выпусков» — доска, дубликаты и кэш, оценка и проверка до
запуска, черновик, серия и выжимка, расписание и уведомления, отклик,
уборка — проверено тестами на фейках и прогоном `python -m aiplatform.smoke --fake`. С
настоящим Telegram (getChat, getChatMemberCount, страница embed) отклик не
проверялся; системные уведомления osascript — тоже. Первый `make smoke`
на этой машине стоит запустить руками.
