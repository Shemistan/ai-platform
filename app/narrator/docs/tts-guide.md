# Как готовить текст для озвучки Supertonic 3

Этот документ — правила для любого текста, который пойдёт в озвучку:
`script.txt` статьи, текст выпуска студии, сценарий видео. Агент читает его
перед тем, как писать такой текст. Статью будут слушать в наушниках,
без экрана, возможно на ходу. Поэтому задача — **пересказать статью для уха
полностью**, а не прочитать разметку страницы и не ужать до аннотации.

Правила из раздела «Ограничения модели» проверены на Supertonic 3: фраза
озвучивалась, озвучка распознавалась Whisper, результат сравнивался с текстом
(примеры — в [спеке](superpowers/specs/2026-09-18-article-narration-design.md)).
Большую часть этих правил ловит `./narrate lint`.

Текст, не приведённый к этим правилам, тоже озвучится: цифры, латиницу и
сокращения переводит в произношение нормализатор (`src/narrator/normalize.py`,
результат покажет `./narrate normalize <файл>`). Он работает по словарям и
правилам и смысла не понимает, поэтому пересказ, написанный по этому
документу, звучит точнее: верные падежи, знакомые названия, разнесённые по
фразам термины.

## Формат файла

- Абзацы разделяются пустой строкой. Каждый абзац озвучивается отдельным
  клипом, между абзацами пауза 0,7 с.
- Заголовок раздела — абзац, который начинается с `# `. Перед ним пауза 1,2 с,
  после — 0,6 с.
- Абзац — 2–6 предложений, предложение — до 250 символов, лучше 10–25 слов.
- Любой блок, включая заголовок, — **не меньше трёх слов**. Одно-два слова
  отдельным клипом модель коверкает: «Нейросети» → «Не Россия». Пиши «# Часть
  третья. Нейросети.» или «# Переходим к нейросетям.».

## Структура

1. **Вступление** — первый абзац: название статьи, откуда она и кто автор.
   «Как мы ускорили сборку в десять раз. Статья с Хабра, автор Иван Петров.»
   Для перевода добавь: «Перевод с английского.»
2. **Основной текст** — по разделам оригинала, с озвучиваемыми заголовками.
   Порядок и логика автора сохраняются.
3. **Концовка** — короткий абзац: главный вывод статьи одной-двумя фразами.
   Без «спасибо за внимание».

## Как адаптировать содержание

- **Полнота.** Всё содержательное остаётся: аргументы, примеры, цифры,
  выводы. Выкидывай только то, что без экрана бессмысленно.
- **Выкидывай:** навигацию, рекламу, «подписывайтесь», призывы поставить
  лайк, сноски `[1]`, «см. рисунок 3», подписи к картинкам без смысла, списки
  ссылок, комментарии читателей.
- **Иностранная статья** — полный перевод на русский, естественным языком, не
  дословно.
- **Код** не читай и в текст озвучки не вставляй вовсе: ни блоков, ни
  фрагментов в строке. Это касается и SQL-запросов, и вывода команд
  (план эксплейна, логи, таблицы чисел). Скажи словами, что он делает и
  зачем: «функция берёт список заказов и возвращает только оплаченные»,
  «запрос выбирает все строки таблицы, и база читает её целиком». В видео
  сам код можно показать на слайде — но слушатель его не слышит. Короткую команду можно
  назвать: «команда пип инстолл».
- **Таблица** — скажи, что в ней сравнивают, и перескажи выводы, которые из
  неё следуют. Все ячейки подряд не читай.
- **Список** — связный текст: «Причин три. Первая… Вторая… И третья…».
- **Формулы** — словами, по смыслу: «время растёт пропорционально квадрату
  числа элементов».
- **Картинки и графики** — если в тексте на них опираются, скажи, что на них
  видно.
- **Цитата** — «Как пишет автор, …» или «По словам Ивана Петрова, …».
- **Ссылки** — не читай. Если важно, куда ведёт ссылка, назови ресурс словами.
- **Термины** при первом упоминании поясни, если слушатель может их не
  знать. Дальше называй одинаково.

## Ограничения модели

| Что | Как писать | Почему |
|---|---|---|
| Цифры, проценты, валюты, единицы | словами и в нужном падеже: «в две тысячи шестнадцатом году», «сорок два процента», «десять гигабайт» | «42%» модель прочла как «42 пациента» |
| Версии | «версия три точка двенадцать», «Такотрон два» | цифры запрещены |
| Латиница | кириллицей, как произносят: «Гитхаб», «Кубернетес», «Постгрес», «Питон» | «API» → «ПИ», «MCP» → «МСИП», «PostgreSQL» → «посгресс Куэлл» |
| Составные названия | раздельными словами: «Опен Эй Ай», «Гугл Дипмайнд» | «Оупен-Эй-Ай» → «А Упина и Ай», «Опенэйай» → «А пенаяй» |
| Слова капсом | кириллицей, как произносят, без капса: «эксплейн», «эксплейн аналайз», «селект», «лимит», «буферс». Капс модель считает аббревиатурой и читает по буквам. На экране слово останется в оригинале — на слайде, не в тексте озвучки | «EXPLAIN» → «е икс пэ эль…», «SELECT» → «эс е эль…» |
| Ссылки, адреса, пути | не пиши вовсе. Если важно, откуда материал, назови ресурс словами: «из документации Постгреса» | «https://…» модель читает по символам или пропускает |
| Аббревиатуры по буквам | раздельно: «эй пи ай», «эс кью эль», «Ай Би Эм». Читаемые словом — словом: «джейсон» | капс кириллицей модель читает непредсказуемо |
| Русские аббревиатуры | лучше развернуть: «искусственный интеллект», «Соединённые Штаты» | «ИИ», «США» — риск |
| Сокращения | полностью: «то есть», «и так далее», «миллионов», «тысяч» | «т.е. и т.д.» → «Тия и Тодейдер» |
| Несколько иностранных названий подряд | разнеси по фразам: «Код лежит на Гитхабе. Запускается в Кубернетесе.» | «Гитхаб, Кубернетес, Постгрес, Докер, Линукс» → каша |
| Ударение | ставится автоматически, см. раздел ниже. Вручную — только чтобы исправить ошибку автоматики: акут после ударной гласной, «зáмок», «замóк». Готовые «á», «é», «ó» тоже можно — lint переведёт их в кириллицу | в `script.txt` **знак «+» запрещён**: Supertonic озвучивает его как призвук, «з+амок» → «бламок» |
| Буква ё | всегда пиши «ё» | без неё модель читает «е» |
| Символы | без скобок, слэшей, звёздочек, `#`, `@`, `&`, `%`, `$`, эмодзи и адресов сайтов. Можно: `. , ! ? ; : - — « » " ' …` | модель их либо пропускает, либо запинается |
| Пояснение в скобках | отдельной фразой или через запятую | скобок нет |

Сомневаешься, как модель прочтёт слово, — перефразируй проще. Короткое
знакомое слово надёжнее редкого.

## Ударения

Модели сами ставят ударения с ошибками. Supertonic произносил
«вырабóтать», «намерéния», «держáт». Поэтому при озвучке каждый абзац
размечается RUAccent turbo3.1, и ударение получает каждое слово. Supertonic
получает ударения акутами, ESpeech — через «+». Автоматике этого хватает
почти везде, но есть два слабых места:

- **Омографы.** RUAccent разбирает их по контексту: «старый зáмок —
  большой замóк», «мýка для пирога — это мукá». Если в предложении мало
  контекста, он может ошибиться. Такое слово стоит проверить и при
  сомнении поставить акут вручную.
- **Сленг и новые заимствования.** Например, «продакт» RUAccent читает как
  «продáкт». Для таких слов есть словарь поправок `FIXES` в
  `src/narrator/stress.py`: там уже «продакт», «фронтенд», «бэкенд»,
  «дедлайн», «фреймворк», «релиз».

Порядок приоритета: акут в `script.txt`, затем словарь поправок, затем
RUAccent.

Проверка распознаванием ошибок ударения не видит: Whisper узнаёт слово при
любом ударении. Их находит только человек на слух.

## Проверка

1. `./narrate lint <каталог>` — ошибки исправь все. Предупреждения прочитай:
   `CAPS`, `HYPHEN_CHAIN`, `SHORT_BLOCK` почти всегда стоит исправить.
2. Озвучка — `./narrate render`: запускает человек на машине с видеокартой.
   Если нужно быстро, агент озвучивает сам: `./narrate synth <каталог>
   --engine supertonic`. Клипы кэшируются по тексту абзаца.
3. Проверка — в `render` она встроена, отдельно это `./narrate verify
   <каталог>`. Каждый абзац распознаётся обратно, и в `check.md` попадают
   абзацы, где совпало меньше 85 % слов. Распознавание тоже ошибается:
   - латиница в «услышано» («API», «Daisy Bell») — Whisper узнал термин, это
     не ошибка озвучки;
   - число может распознаться цифрами в другом падеже — тоже не ошибка;
   - слово превратилось в другое слово или в бессмыслицу («Нейросети» → «Не
     расцепите») — ошибка, перепиши это место.
   - номер заголовка («Часть пятая») записан цифрой — не ошибка.
4. Исправил `script.txt` — снова `./narrate render`: переозвучатся только
   изменённые абзацы. Хватит двух кругов, оставшееся упомяни в отчёте.
